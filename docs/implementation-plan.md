# 구현 계획서

[Spec.md](Spec.md) 12절의 마일스톤을 작업 단위로 풀어 진행 상태를 추적하는 문서다. 요구사항의 정본은 Spec.md, 클라이언트 규약의 정본은 [client-contract.md](client-contract.md)이다. 이 문서와 다르면 그쪽이 먼저이고 이 문서를 고친다.

## 1. 사용법과 갱신 규칙

- 작업 ID는 `M{마일스톤}-{NN}` 형식이다(예: `M0-03`). 한 번 붙인 ID는 바꾸지 않는다.
- 상태값은 `대기`, `진행 중`, `완료`, `막힘`, `취소` 다섯 가지다. 막힘과 취소에는 이유를 한 줄 적는다.
- 작업을 시작할 때 `진행 중`으로, 끝낼 때 `완료`로 바꾸고 같은 커밋에 넣는다. 진행 중인 작업은 한 번에 하나만 둔다. 계획서가 묶은 작업 묶음은 하나로 보며, 묶음 안의 작업은 함께 `진행 중`일 수 있다.
- 마일스톤 하나는 "구현 → 검증 → 사용자 확인"을 마친 뒤 다음으로 넘어간다. 종료 체크리스트는 각 마일스톤 상세 절의 끝에 있다.
- 상세 절은 마일스톤마다 하나이고 대시보드 행과 1:1이다(3 M0, 4 M1, 5 M2, 6 M3, 7 M4, 8 M5, 9 M6, 10 MA, 11 P2). M0~M3은 완료(M3은 부분 종료) 형식으로 정리했고 M5는 착수 전 상세 계획(8절)이 있다. 보류·대기 중인 M4·M6·P2는 착수할 때 같은 형식(작업 표, 완료 기준 표)으로 상세화한다.
- 완료한 마일스톤은 작업 표를 한 줄 요약으로 접는다.

A가 막히면 B·C는 진행하고 D·E는 보류한다. 스파이크 결과가 "허용 밖 도구를 CLI가 막지 못함"(M5-01 ①)이면 M5-13·14가 서버 중계(`tools/list` 필터)로 커지고, "`WebFetch`를 CLI 규칙으로 못 막음"(②)이면 M5-11이 서버 `web_fetch`를 만드는 큰 작업이 되며 M5-09의 `--tools` 구성도 달라진다. 이때는 해당 작업을 쪼개 작업 표를 고친 뒤 착수한다. **계약 변경은 같은 커밋**(CLAUDE.md): M5-02·04·09·13 등 계약(2.5·2.6·오류 코드·엔드포인트)을 바꾸는 작업은 그 작업의 커밋에서 client-contract를 함께 고치고, M5-17은 최종 점검만 맡는다. Spec 5.6과 이 계획서 13절이 "M5 첫 작업"으로 정한 `.gitignore`(`server/mcp-servers.yaml`)는 M5-01에서 하고, 예시 파일(`mcp-servers.example.yaml`)은 스파이크가 정하는 차단 방식을 반영해야 하므로 M5-12에서 커밋한다.

**이월**
- **M5**: 외부 MCP는 v1 `mcp_client_config`가 http만 만들어 stdio 항목(`command`·`args`·`env`)과 외부 서버 목록을 새로 만든다(M5-12). 첨부 `purge_orphans` 안전장치는 M5-07에서 처음 만든다. 페르소나 규칙 중 검색·첨부 절(`rules.py`, 메일 절은 제거)은 도구가 생기는 M5에서 다듬고 프롬프트 스냅샷을 다시 만든다.
- **M6**: 접근성 점검(확인 창·시트의 포커스 가두기, 메뉴 화살표 키 이동, 확인 창을 닫을 때 큰 버튼으로 포커스 복귀, `starting`·`closing`에서 버튼이 잠길 때 포커스 유지, 길게 누르기의 키보드 대체). 빈 DB에서 두 세션이 동시에 처음 시작되면 `persona` 시드가 겹쳐 `UNIQUE constraint failed: persona.id`가 날 수 있다(병렬 E2E에서 1회 관찰, 시드를 한 번만 하게 고친다). 웹 글꼴(Noto Sans KR)은 시스템 글꼴로 대체했고 오프라인 PWA에 맞는 자체 호스팅은 M6에서 정한다. CSRF 검사.
- **자체 음성 재개 때(M4·M3-18)**: 서버 `cancel` API와 `lastPlayed` 정밀 기록, 쉬기 버튼·오프라인 큐 저장소(`LocalQueue`)·맞장구·병합의 화면 연결, `prepare`, 무발화 클라이언트 타이머, 합성을 문장 전송과 분리해 병렬로 하는 구조(지금은 문장마다 합성을 기다린 뒤 보낸다), 동시 보이스 샘플 요청 합치기, 새로고침 복원과 처리 중에 한 말의 메모리 큐(지금은 새로고침하면 사라지고 음성 대화는 글 입력줄로 복원됨)를 IndexedDB 큐로, `voice.resume` 거절 때 글 입력줄로 열리는 드문 경로 정리. 약 15MB wasm의 캐시 헤더, platform 청크 크기(`chunkSizeWarningLimit`)·`optimizeDeps`, `dist/vad` 정적 서빙 E2E도 그때 확인한다. 일지의 "음성으로 이어서"는 다시 열기 응답을 기다린 뒤 재생해 iOS Safari에서 소리가 막힐 수 있다(폰 확인 항목, 막히면 누르는 시점에 오디오를 미리 연다). 검색 안내 음성(`tool.notice` 재생·마이크 임계값 전환)은 검색이 생긴 뒤의 몫이고 `first_sound_notice`는 필드만 있다.
- SSE keep-alive: 도구가 오래 걸리면 Tailscale 터널 등이 유휴 연결을 끊을 수 있다. 폰 접속·지연을 재는 때 확인하고 필요하면 주기적 주석 이벤트를 넣는다.

**알아 둘 점**
- 답변 속 목록 뒤에 이어지는 일반 문단은 서버가 문장을 줄바꿈 없이 나눠 보내 마지막 목록 항목에 붙는다(필요하면 서버가 문단 경계를 보내는 계약 변경으로 푼다). 두 탭에서 동시에 대화하는 경우는 범위 밖이다(기억한 세션 ID는 내 대화일 때만 지운다). 맥북이 잠들면 실제 CLI 평가가 멈춘 것처럼 보이니(서버 결함 아님) 평가 중에는 잠들지 않게 한다.
- **M3에서 정한 동작(음성 재개 때 참고)**
  - 상태 머신은 v1 완성형(`transitions.json` 전이 사례 포함)을 그대로 이식했다. 재생 중에도 마이크를 켜 두고 재생 중 임계값(`setVadMode playback`)으로 캐릭터 목소리를 거른다.
  - 끼어들기는 턴 요청 연결을 끊고 재생을 멈추는 데까지만 연결했다. 큰 버튼은 듣기 중 `tap`이 무동작이고 대화종료는 보조 버튼이 확인 창을 연다.
  - 종료 확인은 `cancelTurn` 뒤 `endSession`을 부르고 `turn_in_progress`면 0.5초 뒤 최대 3번 다시 부른다. `playback_idle`이 `turn_done`보다 먼저 와도 머신은 `turn_done` 뒤에 다음 상태로 간다.
  - 서버가 끝낸 턴은 `end_session`이면 마무리 멘트를 받아 정리로, `pause_session`이면 쉬기 상태로 간다. 무발화 종료는 서버 안전망(`IDLE_TIMEOUT_S`)만 쓴다.
  - 첫 턴의 CLI 콜드 스타트는 `cli_age_ms`로 분리해 보고하고 지연 판정은 M4(60턴)다. `speech_text`의 숫자·단위 변환은 하지 않았고(읽기 어려운 사례가 실측에서 나오면 추가), 한 턴에서 합성이 최종 실패하면 남은 문장은 합성하지 않고 글로 보낸다.
  - ffmpeg는 선택 의존이다(`brew install ffmpeg`는 README). 음성 모듈 의존성은 `@ricky0123/vad-web`·`onnxruntime-web`·`mediabunny`다.

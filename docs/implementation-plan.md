# 구현 계획서

[Spec.md](Spec.md) 12절의 마일스톤을 작업 단위로 풀어 진행 상태를 추적하는 문서다. 요구사항의 정본은 Spec.md, 클라이언트 규약의 정본은 [client-contract.md](client-contract.md)이다. 이 문서와 다르면 그쪽이 먼저이고 이 문서를 고친다.

## 1. 사용법과 갱신 규칙

- 작업 ID는 `M{마일스톤}-{NN}` 형식이다(예: `M0-03`). 한 번 붙인 ID는 바꾸지 않는다.
- 상태값은 `대기`, `진행 중`, `완료`, `막힘`, `취소` 다섯 가지다. 막힘과 취소에는 이유를 한 줄 적는다.
- 작업을 시작할 때 `진행 중`으로, 끝낼 때 `완료`로 바꾸고 같은 커밋에 넣는다. 진행 중인 작업은 한 번에 하나만 둔다. 계획서가 묶은 작업 묶음은 하나로 보며, 묶음 안의 작업은 함께 `진행 중`일 수 있다.
- 마일스톤 하나는 "구현 → 검증 → 사용자 확인"을 마친 뒤 다음으로 넘어간다. 종료 체크리스트는 각 마일스톤 상세 절의 끝에 있다.
- 지금 상세하게 쓰는 것은 M0~M2이다. M3~M6은 착수할 때 같은 형식(작업 표, 완료 기준 표)으로 상세화한다.
- 완료한 마일스톤은 작업 표를 한 줄 요약으로 접는다.

**목표**: 글 대화를 "검색하고 출처를 밝히며, 파일을 보고, 설정할 수 있고, 메일로 보내는" 수준으로 넓힌다. 웹 검색 도구와 출처 인용(FR-20), 파일 첨부(FR-22), 설정 화면(FR-17), 이메일(FR-21), 남은 토큰 막대(FR-23), CLI 내장 `WebFetch` 차단(D7), 서버 설정 파일의 외부 MCP 연결(FR-25, D8)을 만든다. 내용·완료 기준의 정본은 Spec 12절·5.6이고, 첨부·사용량·프로필·도구 요약의 계약은 이미 [client-contract.md](client-contract.md) 1.3·2.5·2.6·2.13·4.1에 적혀 있다(M5는 계약을 구현하고 스파이크 결과로 확정할 부분만 고친다).

**착수 전 현재 상태(코드 확인 2026-11-01)**: 서버에는 프로필 API(`email`·`chat_model` 저장, `mail_ready`는 항상 `false`)와 내부 MCP 도구(`save_note`·`search_notes`·`set_model` 등)가 있고, `persona/rules.py`에 검색·이메일·첨부 규칙 상수(`WEB_SEARCH_RULES`·`EMAIL_TOOL_RULE`·`ATTACHMENT_RULES`)가 있으나 프롬프트 조립에는 아직 연결하지 않았다. CLI는 `--tools ""`·`--allowedTools mcp__trailtalk__*`로 내장 도구를 모두 끈 상태다. DB에는 `turn.sources`·`conversation_session.summary_cites`·`citations`·`note.cites` 열이 있으나 `attachment` 테이블은 없고 일지 상세의 `turns[].attachments`는 항상 빈 목록이다. CLAUDE.md가 말하는 `purge_orphans`(DB에 없는 첨부 정리)도 아직 코드에 없고 M5-07에서 처음 만든다(그전까지 검증 서버는 첨부 폴더를 지우지 않는다). `GET /api/usage`와 설정 화면(하단 탭에 "준비 중" 자리만 있음)은 없다. 서버 의존성에 `Pillow`·`pypdf`가 없다. v1(`~/pythonProject/TrailTalk/`)에 같은 기능의 검증된 구현이 있어(`server/app/services/search.py`·`naver.py`·`mail.py`·`attachments.py`, `api/usage.py`, 웹 `core/usage.ts`·`attachments.ts`·`settings.ts`·`SettingsScreen.tsx`, 스파이크 문서 `docs/spikes/`) 이식을 기본으로 하되 v2 규약(서비스 계층·계약·시각 기준)에 맞춰 다시 쓴다.

**범위 밖(자체 음성 보류 D9와 다른 마일스톤 몫)**: 설정의 보이스 선택·말 속도·맞장구·음성 원본 보관(FR-17 보류 항목, 시안 설정 02·03의 해당 부분), 대화 05 "검색 중"의 검색 안내 음성과 음성 세션의 검색 안내 `notice`, 음성 세션의 첨부(계약상 400), 검색 턴의 **음성** 지연 판정(아래 확인 필요 1), 키워드 검색 `q`·Markdown 내보내기·주간 브리핑(P2), CSRF·PWA·iOS(M6). 시안에는 있지만 이 목록 때문에 만들지 않는 부분은 해당 작업 행에 적었다(CLAUDE.md 화면 디자인 규칙).

**확인 필요(착수 전 사용자 결정)**
1. **검색 턴 지연 판정**: Spec 5.1의 검색 턴 목표(첫 답변 소리 7.5초/p90 9.0초, 안내 소리 4.0/5.0초)는 실제 폰의 음성 경로를 재는 기준인데 자체 음성은 보류다. M3-18과 함께 모든 개발이 끝난 뒤로 이월하고, M5에서는 글 대화의 검색 턴 서버 구간(첫 토큰까지·`search_used`)을 `turn_latency`에 남겨 기준선만 만드는 것을 제안한다(M5-16). 동의하면 Spec 12절 M5 완료 기준("검색 턴 지연 판정")·5.1 수락 기준("검색 턴 목표는 M5에서 판정")·8절 추적표 NFR-01의 "M5 검색 턴"을 같은 커밋에서 "M3-18과 함께 모든 개발 뒤"로 고친다.
2. **키·계정**: 검색(Tavily·네이버 API 키), 이메일(SMTP 계정), 외부 MCP 후보 서버(HasData 키)는 값을 `.env`에만 두고 저는 읽지 않는다. 가진 것을 알려 주시면 그에 맞춰 실제 점검(M5-02·15)을 하고, 없는 것은 가짜 백엔드 시험까지만 하고 실제 점검은 "막힘"으로 둔다.
3. **의존성 추가**: 첨부에 `Pillow`(이미지 재인코딩·썸네일)와 `pypdf`(PDF 쪽수·암호화 검사)가 필요하다(v1과 같은 라이브러리). 의존성 추가는 확인 대상이라 M5-06 착수 때 승인을 받는다. 이메일은 표준 라이브러리 `smtplib`로 충분한지 M5-04에서 정하고 추가가 필요하면 같은 방식으로 묻는다.
4. **외부 MCP 실제 서버**: FR-25는 P2이고 완료 기준은 가짜 서버 E2E다. 실제 서버 1종 연동(M5-15)은 후보가 있을 때만 한다.

**사용량·과금 사전 고지**: 실제 Claude CLI(구독 사용량)·Tavily·네이버·HasData·SMTP를 쓰는 작업은 모두 실행 직전에 알리고 승인을 받는다(M5-01·02·15와 M5-16의 실제 확인). 그 밖의 시험은 모두 가짜(녹화 CLI·가짜 검색·가짜 SMTP·가짜 MCP 서버)로 과금이 없다.

**위험**: 묶음 A는 실제 Claude 사용량과 검색 키에 달려 있다. A가 막히면 B·C는 진행하고 D·E는 보류한다. 스파이크 결과가 "허용 밖 도구를 CLI가 막지 못함"(M5-01 ①)이면 M5-13·14가 서버 중계(`tools/list` 필터)로 커지고, "`WebFetch`를 CLI 규칙으로 못 막음"(②)이면 M5-11이 서버 `web_fetch`를 만드는 큰 작업이 되며 M5-09의 `--tools` 구성도 달라진다. 이때는 해당 작업을 쪼개 작업 표를 고친 뒤 착수한다. **계약 변경은 같은 커밋**(CLAUDE.md): M5-02·04·09·13 등 계약(2.5·2.6·오류 코드·엔드포인트)을 바꾸는 작업은 그 작업의 커밋에서 client-contract를 함께 고치고, M5-17은 최종 점검만 맡는다. Spec 5.6과 이 계획서 9절이 "M5 첫 작업"으로 정한 `.gitignore`(`server/mcp-servers.yaml`)는 M5-01에서 하고, 예시 파일(`mcp-servers.example.yaml`)은 스파이크가 정하는 차단 방식을 반영해야 하므로 M5-12에서 커밋한다.

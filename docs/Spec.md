# TrailTalk v2 Spec

이 문서는 [Intent.md](Intent.md)의 의도를 구현 가능한 명세로 풀어 쓴다. 근거는 v1 저장소(`~/pythonProject/TrailTalk/`)의 `docs/requirements-design.md`, `docs/client-contract.md`, `docs/handoff.md`와 코드다.

- **v1 계승**: v1에서 동작을 확인한 규칙은 그대로 가져온다. 세부 필드·오류 코드는 [client-contract.md](client-contract.md)가 정본이다(v1 규약을 옮기고 v2 변경을 반영했다. 바꾸는 규칙은 10절).
- **v2 변경**: v1의 한계(Intent 9절)를 푸는 항목은 `[v2]`로 표시한다.
- **결정**: 결정 항목은 13절에 모았다.

## 1. 범위

| 구분 | 포함 | 제외 |
|---|---|---|
| 플랫폼 | 웹 앱(PWA) + FastAPI 서버, 본인 Mac에서 구동, 폰은 Tailscale HTTPS. 지원 브라우저는 확인한 Android Chrome이며 iOS Safari는 M6에서 확인해 결과만 기록한다(보증 없음) | 안드로이드·iOS 네이티브, 공개 인터넷 노출, 다중 사용자 |
| 대화 | 핸즈프리 음성 대화, 글 대화(보조), 파일 첨부(글 대화만) | 다중 캐릭터 동시 사용, 음성 세션의 파일 첨부 |
| 기록 | 대화 전문, 요약, 아이디어·할 일·메모, 인용, 검색, 이어서 하기 | 협업·공유 |
| 운동 데이터 | 없음 | 건강 앱 연동, GPS 추적 |
| 후순위 | 마크다운 내보내기(P2), 주간 브리핑(P2), 일지 조회 MCP(P2) | |

웹의 한계로 **백그라운드 대화는 지원하지 않는다.** 화면을 켠 상태(Screen Wake Lock)가 전제이며, 이어폰 버튼은 Media Session으로 재생 중에만 보조한다.

## 2. 용어

- **세션**: 시작부터 종료까지의 한 대화. 하루 등산 1회가 보통 세션 1개다. 끝난 세션을 다시 열어 같은 세션으로 이어 갈 수 있다.
- **턴**: 사용자 발화 1번과 캐릭터 답변 1번. DB에는 `role`별 행으로 저장한다.
- **일지**: 세션 1개의 정리 결과(제목·결론·알게 된 것·확인할 것·노트·인용)와 전문.
- **노트**: `idea` / `todo` / `memo` 중 하나. 별표(`starred`), 완료(`done`)를 가진다.
- **페르소나**: `personas/*.yaml`의 캐릭터 설정. 모델의 고정 정체성이 아니다.


### 4.3 계층 규칙

1. **클라이언트는 얇게**: 녹음·VAD·재생·화면만. 문장 분할, 요약, 중복 제거, 마크다운 정리 등 서버가 할 수 있는 일은 서버에 둔다.
2. **순수 core**: `web/src/core/`(세션 상태 머신, 오프라인 큐)는 UI·브라우저 API에 의존하지 않는다. 마이크·재생·저장소는 `AudioInput`·`AudioOutput`·`LocalQueue` 인터페이스 뒤에 둔다. 린트로 강제한다 `[v2]`.
3. **페르소나 단일 출처**: 캐릭터 이름·성격·말투·보이스·안내 문구(`closing`, `search_notice`, 오프라인 안내)는 `personas/*.yaml`에만 둔다. 시스템 프롬프트는 `app/persona/prompt.py`의 조립기 한 곳에서만 만들고, 앱 동작 규칙은 `rules.py`에 둔다. 캐릭터 이름이 코드에 있으면 실패하는 테스트를 둔다.
4. **CLI 호출 단일 출처**: 실행 인자·환경은 `app/llm/claude_cli.py`의 `build_command`·`build_oneshot_command`·`build_env`뿐이다. 자식 프로세스 환경은 허용 목록(`ENV_ALLOWLIST`)만 넘긴다. `session.send()`는 `contextlib.aclosing`으로 감싼다.
5. **즉시 기록**: 사용자 메시지는 받자마자, 답변은 `sentence`를 보내기 전에 문장마다 저장한다.
6. **오류 형식**: 모든 서버 오류는 `AppError(code, message, status)`로 던지고 `{"error": {code, message, request_id, details}}`로 응답한다. 응답마다 `X-Request-ID`를 둔다.

## 5. 핵심 동작 명세

### 5.1 응답 지연 `[v2]` (D1 확정)

#### 근거: v1 실측 분석

v1 서버가 남긴 `turn_latency` 기록(2026-10-18~21, 실제 사용 314행 중 클라이언트 보고가 있는 255행)을 구간별로 다시 계산했다. 검색을 쓴 턴(32, 그중 2턴은 검색 안내 음성이 먼저 나갔다)을 빼면 223턴이다. v1 handoff의 "약 6.0초"는 10-20 폰 세션(짧은 질문 11턴)의 값이고, 아래 표는 나흘 전체라 더 느리다. 시간은 모두 **실제 말 끝 → 첫 답변 소리**(초)다.

| 구간 | 중앙값 | p90 | 10-20 중앙값 | 비고 |
|---|---|---|---|---|
| 말 끝 → 요청 시작(무음 대기) | 1.85 | 1.91 | 1.85 | 거의 상수. 무음 1.8초 + 인코딩 |
| 오디오 전송(upload) | 0.06 | 0.37 | 0.01 | 말이 길수록 커진다 |
| 음성 인식(STT) | 0.88 | 1.40 | 0.81 | 말 길이에 비례: 오디오 크기 3분위(각 74~75턴)로 0.78 / 0.85 / 1.08 |
| CLI 첫 글자(STT 끝 → 첫 토큰) | 2.00 | 3.38 | 1.78 | 일자별 중앙값 2.00/1.95/1.78/3.12(10-21, 18턴). Claude 쪽 편차 |
| 첫 문장 완성 + 합성(첫 토큰 → 문장 송신) | 1.81 | 3.36 | 1.84 | 이 중 합성만 중앙값 1.77, p90 3.83. 합성이 3초를 넘은 턴 21% |
| 전달·디코드 | 0.29 | 1.01 | 0.17 | |
| **합계** | **7.45** | **10.62** | **6.90** | 일자별 7.37 / 7.95 / 6.90 / 9.17 |

구간 중앙값의 합은 6.89로 합계 중앙값 7.45와 0.56 차이가 난다(꼬리가 긴 분포).

- **분포**: 3초 이내 0%(223턴 중 0), 5초 이내 2%, 6초 이내 11%, 8초 이내 61%, 10초 초과 15%. 최소값 4.67초, 하위 10%가 5.96초다.
- **3초는 이 구조로 불가능하다**: 무음 대기만 1.85초다. 모든 구간이 동시에 각자 하위 10% 값(STT 0.68, CLI 1.26, 첫 문장 1.22 등)이어도 합계는 약 5.1초다.
- **꼬리의 원인**: 15초를 넘은 턴은 4건(17.4, 20.3, 23.1초 등)이다. 가장 느린 두 턴(20.3초, 23.1초)은 첫 문장 합성이 15.0초에 걸린 경우다(합성을 잰 96턴 중 2건. v1 코드의 현재 설정은 시도당 8초·최대 3회라 그 뒤 바뀐 것으로 보이며, 이 15초 값은 당시 기록이다). 상위 꼬리의 나머지는 CLI 첫 글자 지연(5~8초)이다.
- **검색 턴**(안내 음성 2턴 제외 30): 합계 중앙값 7.70, p90 8.67. 검색 안내 음성이 먼저 나간 2턴은 3.87~4.97초에 첫 소리가 났다(표본이 작다).
- **답변 길이**: 답이 80자 미만이면 중앙값 6.49, 150~250자면 7.85. 첫 문장이 길수록 느리다.
- **측정되지 않은 것**: 맞장구(`ack_ms`)는 구현 전이라 기록이 없다. 끼어든 뒤 취소 대기는 기록된 33건 중 26건이 0ms(최대 10ms)였고 CLI 강제 종료(`cli_abort=killed`)는 3건이라 병목이 아니다.

#### 목표

#### 결정과 규칙

- **무음 1.8초는 유지한다.** v1에서 사용자가 정했고(걸으며 쉬는 말이 끊기는 문제), 단축해서 얻는 시간(약 0.9초)보다 쪼개진 말이 생기는 비용이 크다(시나리오 E: 쉬며 이어 말한 6회 중 5회가 쪼개져 앞말에만 답했고 뒷말 답이 13~27초 늦었다). D1로 위 목표값을 확정했다(2026-10-22).
- **맞장구 소리**: 요청을 보낸 뒤 `ack_delay_ms`(기본 300)가 지나도 첫 문장이 재생 대기열에 없으면 짧은 소리를 재생한다. v1 실측상 첫 문장은 요청 후 최소 2.8초라 사실상 모든 음성 턴에서 재생된다. 말이 1초 미만이거나 글 입력이면 건너뛴다. 검색 턴에서는 맞장구에 이어 검색 안내 음성이 평소처럼 나간다(안내가 맞장구를 대신하지 않는다). 첫 문장이 맞장구 재생 시작 후 300ms 안에 오면 맞장구를 페이드아웃하고 답을 이어서 재생한다. 사용자가 다시 말하면 즉시 멈추고, 설정에서 끌 수 있다. 맞장구가 나가는 동안은 재생 중 VAD 임계값(`playback_*`)을 적용한다. 바람·숨소리로 `speech_end`가 나면 인식 결과(`no_speech`)가 나오기 전에 맞장구가 나갈 수 있으며, `ack_min_speech_ms`(기본 1000)로만 줄인다. 맞장구 문구·소리는 페르소나 YAML에 둔다. 클라이언트 지연 보고에 `ack_ms`를 더하고, `request_to_playback_ms`와 첫 답변 지표는 맞장구를 제외한 첫 답변 문장 기준으로 유지한다.
- **계측**: 구간별 값(`upload_ms`, `stt_ms`, `first_token_ms`, `first_queued_ms`, `first_synth_ms`, `synth_wait_ms`, `first_sentence_ms`, 클라이언트 보고 2종, `ack_ms`, `cli_age_ms`, 검색 여부, 답변 글자 수)을 v1처럼 기록하고 `GET /api/latency`에서 검색 턴을 분리해 중앙값·p90을 낸다.
- **수락 기준**: 가짜가 아닌 실제 폰에서 검색하지 않은 60턴 이상을 사흘 이상에 걸쳐 재서 전체 중앙값·p90이 위 표를 충족한다(v1 일자별 중앙값이 6.9~9.2초로 흔들렸으므로 일자별 중앙값도 함께 보고한다). M3에서 30턴으로 먼저 구간 표를 채워 기준선을 만들고 M4에서 60턴으로 판정한다. 검색 턴 목표는 M5에서 판정한다. 달성하지 못하면 구간별 표로 어느 구간이 예산을 넘겼는지(특히 CLI 첫 글자가 2.0초를 넘는 날은 Claude 쪽 편차인지) 보고하고 목표를 다시 정한다. 도전 목표는 보고만 한다.

### 5.2 음성 합성 `[v2]`

- TTS는 `TtsBackend` 인터페이스 뒤에 둔다. 기본 `gpt-4o-mini-tts`(말투 지시 적용), 대체 `tts-1`(말투 지시 미적용).
- 문장 단위 합성에 **타임아웃**을 둔다(v1 실측: 첫 문장 합성 중앙값 1.77초, p90 3.83초, 3초 초과 21%, 합성이 15초 걸려 20초 넘게 걸린 턴 2건). 시각은 모두 그 문장의 합성 요청 시작 기준이다. 첫 문장은 3초가 지나도 소리가 없으면 같은 요청을 한 번 더 보내고(헤징), 5초에 대체 모델 요청을 더하며(동시에 최대 3개), 먼저 오는 결과를 쓰고 나머지는 취소한다. 별도로 턴의 요청 시작 후 12초가 지나도 소리가 없으면(CLI 지연 포함) 글을 먼저 보내 기기 TTS로 읽는다. 둘째 문장부터는 재생 중에 합성하므로 문장당 6초 타임아웃에 1회 재시도 → 대체 모델을 쓴다(v1은 시도당 8초·최대 3회였다). 최종적으로 실패하면 `sentence.audio = null`로 글만 보내되 `speech_text`를 함께 보낸다. 클라이언트는 `audio`가 `null`인 문장의 `speech_text`를 기기 TTS(`speechSynthesis`, ko-KR)로 읽는다.
- 문장마다 사용한 모델(`tts_model`)과 폴백 발동 비율을 로그·`/api/latency`에 남긴다. 폴백 사실을 화면에 표시하지는 않는다(목소리는 바뀔 수 있다).
- 수락 기준: 100문장 연속 합성에서 소리 없이(기기 TTS 폴백도 없이) 빠지는 문장 0개. 폴백 발동 비율을 보고하고 기본 모델 문장 중 `tts-1` 또는 기기 TTS로 넘어간 비율이 10%를 넘으면 기본 모델 변경을 검토한다.
- 숫자·단위는 읽기 쉬운 말로 바꾼 `speech_text`를 합성하고, 화면에는 원문(`sentence.text`)을 보인다. `speech_text`는 마크다운·링크를 지운다. SSE `sentence`는 `audio`가 `null`일 때만 `speech_text`를 싣는다.

### 5.3 세션 상태 머신과 발화 판정

상태: `idle`, `listening`, `processing`, `speaking`, `paused`, `offline`, `closing`. 이벤트·명령·전이 표는 `client-contract.md` 6절과 `shared/fixtures/transitions.json`(사례 33개)를 그대로 이식하고 v2 사례를 더한다. 핵심 규칙:

- 한 번 누르기: `idle`=시작, `speaking`/`processing`=끼어들기, `paused`=다시 듣기. 종료: 화면 아래 조작 영역의 "대화종료" 버튼(`idle`과 `closing` 외 모든 상태에 보임. 글 대화에서는 입력창 아래 버튼 줄)을 누르면 확인 창("끝내고 정리하기" / "계속 대화하기")을 거쳐 종료하고, 큰 버튼 길게 누르기는 같은 종료를 확인 없이 하는 보조 수단이다.
- 듣기·쉬기에서 30분 무발화면 `closing`. 서버도 같은 기준(`IDLE_TIMEOUT_S`)으로 안전망을 둔다. 화면 문구의 "30분"은 설정값에서 읽는다 `[v2]`.
- 모르는 이벤트와 표에 없는 조합은 무시한다. 지금 턴과 다른 ID의 늦은 이벤트는 버린다.
- 재생 중 VAD 임계값을 올려(`playback_*`) 캐릭터 목소리를 사용자 발화로 오인하지 않게 한다. `speech_start`는 `min_speech_ms`(300ms) 이상 이어진 뒤에만 낸다.
- 오프라인: 보내다 서버에 닿지 않으면 녹음을 IndexedDB에 보관하고 기기 TTS로 안내한다. 연결이 돌아오면 오래된 것부터 보통 턴으로 보낸다. 서버가 대화를 끝낸 뒤 도착한 말은 `…/turns/audio/record`로 기록만 남긴다.
- **쪼개진 발화 병합 `[v2]` (D2)**: 쉬며 이어 말한 뒷말이 앞말과 따로 처리되면 앞말에만 답하고 뒷말의 답이 13~27초 늦는다(v1 시나리오 E: 6회 중 5회). 규칙을 서버에 둔다.
  - **조건**: 한 세션의 앞 턴이 처리 중이고 첫 답변 문장이 아직 클라이언트에 나가지 않았을 때(v1은 이때 클라이언트가 뒷말을 큐에 보관해 앞 답변이 끝난 뒤 보냈다) 클라이언트는 뒷말을 큐에 넣지 않고 바로 보낸다. 서버는 `turn_in_progress`(409) 대신 앞 턴을 대체한다.
  - **서버 동작**: 앞 턴의 생성을 취소하고(앞 턴 SSE는 `done {superseded: true}`로 닫는다) CLI에 "직전 말에 이어서 말함" 안내와 함께 앞말·뒷말을 합친 텍스트를 보내 한 번만 답하게 한다. 앞말에서 이미 호출된 도구(`save_note` 등)는 되돌리지 않으며, 중복 노트는 일지 추출의 중복 제거에 맡긴다.
  - **기록**: 즉시 기록 원칙(4.3.5)에 따라 사용자 턴은 두 행으로 남기고(오디오도 각각 보관), 뒷말 행의 `turn.merged_from`이 앞말 턴 ID를 가리킨다. 화면과 전문은 `merged_from`으로 이어진 두 행을 한 말풍선으로 보인다.
  - **병합하지 않는 경우**: 첫 문장이 이미 클라이언트에 나갔거나, 글 입력 턴이거나, 뒷말이 `merge_min_speech_ms`(기본 600) 미만이거나, 오프라인 큐에 항목이 있을 때는 병합하지 않고 보통 끼어들기·큐 규칙을 따른다.
  - **한계(타이밍 계산)**: 뒷말이 서버에 닿는 시각은 쉬는 시간 + 뒷말 길이 + 1.85초 + 전송·인식(약 1초)이고, 앞 턴의 첫 문장은 v1 실측으로 요청 후 최소 2.8초(중앙값 약 5.2초)에 나간다. 그래서 병합은 쉬는 시간이 약 3초 이내일 때 주로 성공하고 4초 이상 쉬면 대개 놓친다. 쉬는 시간이 무음 대기(1.8초)보다 짧으면 쪼개지지 않으므로 평가 대상이 아니다. 병합을 위해 첫 문장을 일부러 늦추는 대기 창은 두지 않는다(5.1 예산과 충돌).
  - **수락 기준**: 쉬는 시간 2.0, 2.5, 3.0초 각 5회(총 15회)에서 앞말에만 답한 경우 2회 이하. 4.0초 쉬는 5회는 병합 성공 여부를 보고만 한다.
- 발화 끝 무음은 `vad.end_of_speech_silence_ms` 1800으로 고정한다(5.1). 줄이는 것은 현장 데이터가 쌓이고 병합이 안정된 뒤에 다시 검토한다.
- 상태 머신 v2 사례(`transitions.json`에 더한다): 맞장구 시작·끝, 맞장구 중 사용자 발화, 병합 대상 뒷말 즉시 전송, 병합하지 않는 조건 4가지, 병합된 턴에서 `done.superseded` 처리.

### 5.4 화면 표시와 마크다운 `[v2]`

- 답변·일지 요약·메모는 마크다운 부분집합(굵게, 기울임, 링크, 목록, 인라인 코드)만 렌더링한다. 원시 HTML은 무시한다.
- 링크는 `http`/`https`만 활성화하고 `rel="noopener noreferrer" target="_blank"`로 연다. 그 밖의 스킴은 글자로만 보인다.
- 서버는 `sentence.text`에 원문을 싣는다. 음성용 `speech_text`는 합성에 쓰고, 합성이 실패한 문장에만 클라이언트로 보낸다(5.2).
- 일지 상세는 첫 줄 결론(굵게), 이어서 "알게 된 것", "확인할 것", 인용(`[n] 제목 URL`), 태그 순서를 따른다.

### 5.5 일지 추출 `[v2]`

- 종료 후 요약 모델(`haiku`)이 전문에서 JSON(제목, 요약 3줄, 아이디어[], 할 일[], 메모[], 태그[], 확인할 것[], 인용)을 낸다. `--json-schema`로 출력을 고정하고 서버에서 다시 검증한다.
- `save_note`로 대화 중 이미 저장된 항목과 겹치는 것은 거른다. 중복 판정은 **보수적**으로, 표현만 다른 중복은 추출 지시에 맡기고 문자열 유사도 규칙으로 지우지 않는다(v1에서 "치과 3시/5시"가 같은 항목으로 지워진 사례).
- **수락한 제안만 아이디어로**: 아이디어는 ① 사용자가 직접 말한 것, ② 캐릭터가 제안했고 사용자가 긍정으로 답한 것만 뽑는다. 침묵, 화제 전환, "음" 같은 응답, 거절은 수락이 아니다. 같은 규칙을 `save_note` 도구 지침에도 적어 캐릭터가 자기 제안을 저장하지 못하게 한다. 추출 평가 12개 중 최소 3개는 이 경우의 정답 케이스로 둔다.
- 추출은 실패해도 대화·전문은 남고 `retry`로 다시 돌릴 수 있다.
- 다시 열어 이어간 세션을 다시 끝내면 요약·태그·확인할 것은 전문 전체로 새로 쓰고, 기존 노트는 지우지 않으며(별표·완료·고친 내용 유지) 새 노트만 더한다. 고친 제목은 유지된다.

내장 도구는 `--tools "WebSearch,WebFetch"`로 제한하고(웹 검색을 만드는 M5 전까지는 `--tools ""`로 내장 도구를 모두 끄고 `--allowedTools`에는 `mcp__trailtalk__*`만 둔다. `--tools`는 외부 MCP 도구와 무관하다), 외부 서버가 없을 때 `--allowedTools "mcp__trailtalk__*,WebSearch,WebFetch"`로 허용 범위를 정한다(외부 서버가 있을 때는 아래 "외부 MCP" 절). MCP 도구가 보이도록 `ENABLE_TOOL_SEARCH=false`를 준다. CLI는 빈 전용 작업 폴더에서 실행하고 버전을 고정한다. 웹 페이지·첨부 속 지시는 사실 정보로만 다루고 따르지 않는다(프롬프트 규칙).

#### 외부 MCP `[v2]` (FR-25, M5)

- 등록은 서버 설정 파일에만 한다. 경로는 환경변수 `MCP_SERVERS_PATH`(기본 `server/mcp-servers.yaml`, 파일이 없으면 외부 서버 없음)이고 검증 서버는 임시 경로로 바꾼다. 예시 `mcp-servers.example.yaml`만 커밋하고 실제 파일은 `.gitignore`한다(M5 첫 작업). 이 파일이 신뢰 경계이므로 파일이나 그 폴더를 그룹·타인이 **쓸 수 있거나** 소유자가 서버 실행 사용자가 아니거나 심볼릭 링크이면 시작을 거부한다. 읽을 수 있으면 경고만 한다(비밀 값은 파일이 아니라 `.env`에 있다). API·화면으로는 등록하지 않는다.
- 항목: `name`(`[a-z0-9-]{1,32}`, 중복과 예약어 `trailtalk`·`servers`는 거부. 서버 이름에는 `_`가 없으므로 `mcp__<서버>__<도구>`의 첫 `__`가 항상 서버와 도구의 경계이고 도구 이름에는 `__`가 있어도 된다), stdio는 `command`·`args`·`env`, http는 `url`·`headers`, `allowed_tools`(필수, 비면 거부, 도구 이름만 `[A-Za-z0-9_-]{1,64}`, `*` 거부). `args`는 문자열 목록이고 비밀을 쓰지 않는다(프로세스 목록에 보인다). 전체 이름 `mcp__<서버>__<도구>`가 64자를 넘으면 시작을 거부한다(CLI 한도가 다르면 M5 스파이크 뒤에 고친다). 서버가 시작할 때 검증하고 틀리면 시작하지 않는다.
- 비밀: `env`·`headers`의 값은 비밀을 파일에 적지 않도록 서버 `.env`의 **변수 이름**만 적는다. 값 안에 `${MCP_<서버>_<이름>}` 형태로 적고(예: `Bearer ${MCP_HASDATA_KEY}`) 서버 이름은 대문자로, `-`는 `_`로 바꾼 것이 접두사다. 각 서버는 자기 접두사 변수만 참조할 수 있다(다른 서버의 변수나 `OPENAI_API_KEY`·`CLAUDE_CODE_OAUTH_TOKEN` 같은 무관한 비밀은 넘길 수 없다). 비밀이 아닌 고정값은 파일에 그대로 적는다. 변수가 없거나 비어 있으면 시작을 거부한다. `url`에는 비밀(쿼리 포함)을 쓰지 않고, 로그에는 쿼리를 뺀 주소만 남긴다.
- CLI 연결: `--allowedTools`는 외부 서버가 없을 때 위 문단의 값이고, 있을 때는 거기에 `mcp__<서버>__<도구>` 항목만 더한다(외부 서버에는 와일드카드를 쓰지 않고 자체 `trailtalk`은 `mcp__trailtalk__*`). `--allowedTools`는 승인 대상 지정이지 차단 수단이 아니므로, 비대화형 모드에서 허용 밖 도구 호출이 거부되는지는 M5 스파이크와 E2E에서 확인한다. 거부되지 않으면 `--disallowedTools`나 서버가 `tools/list`를 걸러 주는 중계를 쓴다. 시작 때 서버에 접속하지 않으므로 허용 도구가 실제로 있는지는 검증하지 않는다.
- 실행: stdio 서버의 `command`는 절대 경로여야 하고(`PATH` 탐색 안 함, `npx`·`uvx`도 절대 경로로 적는다) 셸 없이(`shell=False`) 실행한다. 다만 `npx`·`uvx` 같은 실행기는 내부에서 패키지를 내려받아 실행하므로 실행되는 코드는 설정 파일 작성자가 신뢰해야 한다. 작업 폴더는 CLI 전용 작업 폴더 아래의 빈 하위 폴더이고, 환경은 `env`에 적은 변수와 서버 프로세스의 `PATH`·`HOME`·`LANG`·`TMPDIR`만 넘긴다(서버 `.env` 전체를 상속하지 않는다. CLI 자신의 환경 허용 목록과는 별개다). `--mcp-config`는 인자가 아니라 권한 0600 파일(CLI 프로세스 전용 작업 폴더의 `mcp.json`)로 넘기고, CLI가 끝나면 폴더째 지우며 서버 시작 때 CLI 전용 작업 폴더 아래의 `mcp-*` 폴더만 지운다. 자체 도구는 CLI에서 `mcp__trailtalk__` 접두사로 보이고 SSE에는 접두사를 뗀 이름으로 보낸다.
- 로그·결과: 비밀 값, 외부 서버의 stderr 내용, 도구 인자는 로그에 남기지 않고 외부 도구의 `tool` 이벤트 `input`은 `null`로 보낸다. 외부 도구 결과는 `tool` 이벤트의 `summary.result`로만 나가며 서버가 2000자로 자르고 이 이벤트는 DB에 저장하지 않는다(모델이 답변에 인용한 내용은 일반 답변처럼 `turn.text`로 남는다). 외부 도구 결과는 `turn.sources`·`citations`에 넣지 않는다(출처 인용은 M5 스파이크에서 정한다). 화면은 마크다운으로 렌더링하지 않고 글자 그대로 보인다.
- 인젝션·부작용: 외부 도구 직후 턴의 쓰기 도구(`save_note`·`set_nickname`·`set_model`·`send_email`)는 검색 직후와 같은 서버 검증을 받고, 외부 도구 결과 속 지시는 사실 정보로만 다룬다. 허용 목록 작성자는 도구의 부작용(쓰기·삭제·결제)을 책임지며 읽기 전용 도구만 권장한다. 파일시스템·셸 실행 계열 서버는 허용 목록에 두지 않는다.
- 도구가 많으면 `ENABLE_TOOL_SEARCH=false` 때문에 도구 정의가 프롬프트에 모두 실려 지연·토큰이 늘 수 있다. 서버에서 필요한 도구만 고르게 하고 영향은 M5 스파이크에서 잰다.

### 5.7 프롬프트 조립

한 조립기가 네 블록을 이 순서로 만든다: ① 페르소나(맨 앞에 고정해 프롬프트 캐시 적용), ② 상황(시작 시각, 음성 모드면 5문장 이내·마크다운 금지·숫자 읽기), ③ 기억(최근 7일 일지 요약, 열린 아이디어·할 일, 관심사), ④ 역할 규칙(브레인스토밍 원칙, 모르는 사실 지어내지 않기, 검색 원칙, 인젝션 방어). 현재 시각은 턴마다 사용자 말 앞에 앱 안내 블록으로 붙이고 기록에는 남기지 않는다. `[v2]` **호칭은 세션 시작 인사말에서만 쓴다.** 시스템 프롬프트에는 호칭을 넣지 않고, 인사말을 만드는 요청에만 현재 호칭을 앱 안내로 붙인다. 역할 규칙(④)에 "인사말 이후에는 사용자를 호칭으로 부르지 않는다"를 둔다. 다시 열기의 재개 인사말과 마무리 멘트도 호칭을 쓰지 않는다. 페르소나 `examples`의 `{호칭}` 자리표시자는 인사말 예시에만 둔다. 이 규칙으로 대화 중 호칭을 바꾼 뒤 CLI가 `--resume`으로 다시 떠도 옛 호칭이 남을 일이 없다. 수락 기준: 톤 평가 샘플 20개 중 인사말을 제외한 답변에 호칭이 포함된 것 0개. 프롬프트를 바꾸면 스냅샷 테스트를 갱신하고 차이를 검토한다.

### 5.8 Claude CLI 운영

- 대화: 세션마다 상주 프로세스(`--input-format stream-json --output-format stream-json --include-partial-messages`). 모델은 대화 `sonnet`, 요약·추출 `haiku`, 설정으로 `haiku`/`sonnet`/`opus` 선택.
- 끼어들기: 해당 프로세스에 인터럽트 → 들려준 문장 번호(`last_played`)까지 답변 기록을 자르고 `interrupted` 표시. 다음 턴에만 "어디까지 들었는지" 안내를 CLI에 붙인다.
- 복구: 프로세스가 죽으면 `session_id`로 `--resume`하여 맥락을 잇는다. 다시 열기는 저장된 전문을 새 프롬프트에 넣어 새로 띄운다(긴 전문은 정리 결과 + 최근 원문 약 4천 자).
- 사용량: 답변마다 오는 `rate_limit_event`의 마지막 값을 메모리에 두고 `GET /api/usage`로 낸다. 서버 시작 직후 첫 답변 전에는 `null`.
- `ClaudeCliBackend`를 `app/llm/backend.py`의 인터페이스 뒤에 둔다(서비스화 때 API 백엔드 교체 가능).

## 6. 데이터 모델

ID는 UUID 문자열, 시각은 UTC. 열거값은 DB CHECK 제약, 스키마 변경은 Alembic(모델을 바꾸는 커밋에 마이그레이션 포함, 앱 시작 때 head까지 자동 적용). 열거 CHECK 변경은 batch로 직접 교체한다.

| 테이블 | 주요 컬럼 |
|---|---|
| `conversation_session` | id, mode(text/voice), started_at, ended_at, status(active/paused/ended), title, summary, tags, summary_cites, citations, checks, extract_status(pending/done/failed/null; API 필드명은 `journal_status`), title_edited, reopened_at, persona_id `[v2]`, system_prompt(시작 때 고정), cli_session_id |
| `turn` | id, session_id, seq, role, text, audio_path, interrupted, greeting, sources(출처 JSON), merged_from `[v2]`, created_at |
| `attachment` | id, turn_id(CASCADE), name, mime, size, path, thumb_path, chars, pages. 파일은 `attachments_dir/{session_id}/`(폴더 0700·파일 0600) |
| `note` | id, session_id, turn_id, kind(idea/todo/memo), content, cites, starred, done, created_at |
| `turn_latency` | turn_id, session_id, 서버 단계 ms(upload/stt/first_token/first_queued/first_synth/synth_wait/first_sentence/done), open_llm_ms, cli_resumed, cli_age_ms, cli_abort, cancel_wait_ms, cancel_outcome, sentence_count, reply_chars, tool_count, search_used, 클라이언트 보고 ms, first_sound_notice, ack_ms `[v2]`, tts_model `[v2]` |

| `briefing` (P2) | id, week_start, script_text, audio_path, sources_json |

v1의 `barge_in_event` 테이블과 `POST /api/barge-in-events`, `window.__tt_metrics` 훅은 v2에 이식하지 않는다. 끼어들기 기록이 필요해지면 M4에서 추가한다. `persona_id`는 일지 전문의 화자 이름이 현재 페르소나가 아닌 그 세션의 페르소나를 따르게 하려는 것이다. 프로필 값의 제약(호칭 1~20자, 관심사 10개 등)은 `client-contract.md` 이식으로 갈음한다.

**SSE 이벤트**: `transcript`(음성 턴에서만 첫 이벤트) → `turn` → (`sentence` · `tool`)* → `done` 또는 `error`. 클라이언트는 모르는 `type`·필드·`summary.kind`를 무시한다. 시작 전 오류는 SSE가 아니라 JSON 오류다. 오디오: 업로드 16kHz 모노 Opus(webm, 불가 시 WAV), 응답 문장별 MP3(base64).

**v2 계약 변경(`client-contract.md` 0절 요약표에 반영 완료)**: SSE `sentence.speech_text`(음성 문장이 `audio: null`일 때만 값이 온다), `done.superseded`, 사용자 턴 `merged_from`(DB와 일지 상세 `turns[]`), 지연 보고 `ack_ms`와 요약 지표, `turn_latency.tts_model`, 세션 시작 응답의 `persona.ack`(맞장구 소리), 프로필 `ack_enabled`, 변경성 요청의 `X-TrailTalk` 헤더와 `csrf_rejected`, 병합으로 인한 `turn_in_progress` 처리 변경(5.3), 뒷말 즉시 전송·종료 확인·맞장구에 따른 상태 머신 이벤트와 명령.

**공통 오류 코드(요약, 전체는 `client-contract.md`)**: `session_not_found`, `session_ended`, `turn_in_progress`, `turn_not_found`, `no_speech`, `audio_invalid`, `attachment_invalid`/`_too_large`, `voice_unavailable`, `stt_failed`/`_timeout`, `tts_failed`/`_timeout`, `llm_error`/`_process_exited`/`_timeout`, `note_not_found`, `invalid_range`, `session_not_ended`, `session_active`, `persona_not_found`. 클라이언트 측 코드: `network_error`, `http_error`, `stream_closed`, `bad_event`.

## 8. 화면

**시안**: 화면 시안(라이트·다크, 360 × 800)은 아티팩트 https://claude.ai/artifact/UtHPgV1MqZRsLDEKyEZpaQ 에 있고, 소스 사본과 파일 ↔ 보드 표는 [design/README.md](design/README.md)에 있다. 화면 구성이 시안과 다르면 이 절이 먼저이고 시안을 고친다.

하단 탭 3개(대화 · 일지 · 설정). 일지 상세는 일지 탭 안의 화면이다.

- **대화**: 시작 전(방식 선택 음성/글, 지난 아이디어 카드, 연결 상태, 남은 토큰 막대) → 대화 중(헤더 오른쪽의 남은 토큰 막대는 시작 화면과 같은 위치, 아래 조작 영역 맨 위에 시작 화면과 같은 "음성으로/글로" 선택 버튼, 그 아래 큰 버튼 한 개와 일시 중단·대화종료 보조 버튼(글 대화는 입력창과 대화종료 버튼), 말풍선, 도구 알림, 보관한 말 수, 여러 줄 글 입력(기본 2줄)·첨부) → 정리 중("그만 기다리기") → 끝남.
- **일지 목록**: 날짜별로 묶어 최신순으로만 보인다. 보기 전환과 정렬 선택은 없다. 상태 알약(대화 중·정리 중·실패), 선택 삭제. 진행 중인 대화는 "대화 중" 알약과 강조 테두리로 보이고, 누르면 대화 화면으로 돌아간다. 진행 중인 대화는 지울 수 없다.
- **일지 상세**: 결론·알게 된 것·확인할 것·노트(별표·완료·수정)·인용·전문(첨부 썸네일), 제목 수정, 글/음성으로 이어서, 다시 정리, 삭제. 진행 중이지만 열려 있지 않은 대화에는 "대화 끝내기"를 보인다.
- **설정**: 세 구역으로 나눈다. ① 내 정보: 호칭(1~20자), 이메일(`mail_ready` 표시), 관심사(최대 10개). ② 음성·대화 모델: 보이스(▶로 미리 듣기), 말 속도(0.75~1.5, 기본값으로 되돌리기), 맞장구 켜기·끄기, 대화 모델(haiku·sonnet·opus). ③ 보관·화면·앱: 음성 원본 30일 보관 스위치, 화면 모드(시스템 설정 따르기·라이트·다크, 이 기기에만 적용), 새 버전 적용·서버 연결 상태·캐릭터·버전. 값을 바꾸면 바로 저장하고 헤더 오른쪽에 "저장됨"을 보인다.
- 새 버전은 자동으로 새로 고치지 않고 "새 버전 적용" 버튼으로 바꾼다. 음성 모듈은 지연 로드하며 로드 전에는 "음성으로 대화"를 막는다.

## 9. 보안과 개인정보

- 데이터는 본인 서버에만 둔다. 키(OpenAI, Tavily, 네이버, SMTP)와 Claude 토큰은 서버 `.env`에만 둔다(`.env`는 읽지 않고, 값이 없어도 서버는 시작한다).
- Tailscale Serve로 tailnet 안에서만 HTTPS를 연다. 공개 Funnel은 쓰지 않는다. `/internal/*`(앱 도구 경로)은 프록시 경유 요청을 403으로 막는다.
- `[v2]` **CSRF 방어(NFR-10)** (D3): 변경성 요청(POST/PUT/PATCH/DELETE)은 ① 커스텀 헤더 `X-TrailTalk: 1`을 가져야 한다. 이 헤더가 교차 출처 요청에 CORS 사전 요청을 강제하고 CORS는 열지 않으므로 이것이 주된 방어선이다. ② `Origin`이 있으면 허용 목록(`ALLOWED_ORIGINS`, 기본은 서버 자신의 Tailscale 주소·`127.0.0.1:8000`, 개발 중에는 `localhost:5173`)에 있어야 한다. `Origin`이 없는 요청은 ①을 만족하면 받는다. ③ 본문이 있는 요청은 `Content-Type`이 `application/json`·`multipart/form-data`·지정한 오디오 형식이어야 한다(본문 없는 요청에는 적용하지 않는다). 면제: `/internal/*`(루프백만, 프록시 경유 403), `GET /api/health`. 오디오 업로드처럼 본문이 바이트인 요청도 ①을 요구한다. 수락 기준: 다른 출처 페이지에서 보낸 단순 POST/DELETE가 모두 거절되는 시험.
- 첨부: 서버가 이미지를 재인코딩(EXIF 제거), 텍스트는 `<attachment>` 래퍼로 감싸 안의 지시를 따르지 않게 한다. `GET /attachments/{id}`는 UUID 추측 불가성과 네트워크 경계로 보호한다(`<img>`가 헤더를 못 붙인다). 항상 `X-Content-Type-Options: nosniff`.
- 웹 내용 인젝션: 검색·fetch·외부 MCP 도구 직후 턴의 쓰기 도구는 서버가 검증한다. `set_nickname`·`set_model`·`send_email`은 첨부·웹이 아닌 사용자 발화만 근거로 한다. 알려진 한계: 발화에 "메일"이 있으면 그 턴의 검색 결과가 지시한 본문이 본인 주소로 나갈 수 있다(받는 사람은 바뀌지 않음).
- 음성 원본은 기본 저장하지 않는다. 켜면 본인만 읽을 수 있는 권한으로 30일 보관 후 삭제한다.
- `[v2]` 외부 MCP(FR-25): stdio 서버는 서버 머신에서 명령을 실행하므로 설정 파일 접근이 신뢰 경계다. 외부 서비스형 서버는 모델이 도구 인자로 넣은 내용(검색어·발화 일부, 첨부·일지 내용이 섞일 수도 있다)이 서버 밖으로 나갈 수 있어 NFR-06의 예외이며 예시 파일에 주석으로 밝힌다. 외부 서버가 임의 URL을 가져오는 도구를 제공하면 D7(WebFetch 차단)의 범위 밖이므로 허용 목록으로만 통제한다.

## 10. 규약 관리와 개발 규칙

- 규약(REST, SSE, 상태 머신, 클라이언트 설정값)을 바꾸면 같은 커밋에서 `docs/client-contract.md`, OpenAPI 생성 타입(`npm run gen:api`), 전이 표를 함께 고친다.
- 서버가 새 이벤트·필드를 먼저 더할 수 있으므로 클라이언트는 모르는 것을 무시한다.
- 클라이언트 설정값(`shared/client-defaults.json`)은 서버가 시작할 때 검증하며 틀리면 시작하지 않는다. VAD 수치는 시작값이고 실제 산책 측정으로 조정한다.
- 서버 시작 시 `purge_orphans`가 DB에 없는 첨부를 지운다. 다른 경로(개발·검증 서버)에서는 DB, 첨부, 오디오, CLI 작업 폴더를 **모두** 임시 경로로 바꾼다. 가능하면 `purge_orphans`는 `ATTACHMENTS_DIR`이 기본 경로가 아니면 동작하지 않게 하는 안전장치를 둔다 `[v2]`.

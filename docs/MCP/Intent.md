# TrailTalk × Claude 앱 MCP 연계 Intent

작성일: 2026-10-30. 상태: **제안(미구현)**. 이 문서는 Claude 앱 MCP 연계의 **의도(무엇을, 왜, 어떤 원칙으로)**를 정리한다. 기존 [docs/Intent.md](../Intent.md)를 고치지 않고 덧붙이는 문서이며, 기존 Intent의 "주 장면" 문장을 바꾸는 반영안은 [doc-changes.md](doc-changes.md) 1절에 있다. 결정은 [README.md](README.md), 설계는 [design.md](design.md), 도구 명세는 [tools.md](tools.md), 작업과 진행은 [implementation-plan.md](implementation-plan.md)가 기준이다.

## 1. 한 줄 정의

걷는 중 이어폰으로 하는 **음성 대화는 Claude 앱이 맡고**, TrailTalk 서버는 외부 MCP 서버로서 그 대화에서 나온 일지·노트를 저장하고, 조회·검색·수정·삭제하게 하며, 웹 앱(PWA)에서도 같은 내용을 보고 고칠 수 있게 하는 연계다.

## 2. 왜 만드는가

- 자체 음성 처리(VAD·STT·TTS·상태 머신·지연 계측)는 TrailTalk에서 가장 무겁고 불확실한 부분이다. 음성 품질과 모델 운영을 Claude 앱에 맡기면 이 부담이 사라진다.
- 사용자는 이미 폰의 Claude 앱 음성으로 대화한다. 그 대화가 **TrailTalk의 일지로 남고 다음 대화의 기억이 되면** 별도 앱으로 옮겨 가지 않아도 목적(아이디어를 놓치지 않고 쌓는 것)을 이룬다.
- 시험용 구현(`~/pythonProject/trailTalk-MCP`)이 Claude 앱에서 OAuth 보호 MCP 서버로 실제 쓰인 기록이 있다. v2는 그 경험을 v2의 데이터 모델과 웹 화면 위에 옮긴다.

## 3. 목표

1. **음성으로 저장**: 앱에서 "오늘은 여기까지"라고 말하면 대화가 일지(요약·아이디어·할 일·메모·태그)로 저장된다.
2. **음성으로 관리**: "저장된 아이디어를 목록으로 보여 줘", 별표·완료·내용 수정·삭제, 호칭 변경을 앱 음성으로 한다. 삭제는 2단계 확인을 거친다.
3. **기억 이어 가기**: 앱이 대화를 시작할 때 호칭·최근 일지·열린 아이디어·열린 할 일을 가져와 이어서 말한다.
4. **웹에서도 같은 데이터**: 앱에서 저장한 일지·노트가 웹 일지 화면에 보이고, 웹에서 노트를 고치면 앱이 보는 내용도 바뀐다.
5. **안전한 외부 노출**: 인터넷에 여는 것은 MCP·OAuth 경로뿐이며, 서버 API와 웹 화면은 공개하지 않는다.

## 4. 사용자와 사용 장면

- 사용자는 본인 한 명이다. 인증은 OAuth(소유자 비밀번호)로 하고, 서버는 본인 Mac에서 돈다.
- 주 장면은 걷는 중 이어폰으로 Claude 앱과 음성 대화하는 것이다. 말투와 페르소나는 Claude 계정 지침이 맡고 서버가 통제하지 않는다.
- 집이나 책상에서는 웹 앱 일지 화면에서 저장된 일지를 읽고 노트를 고친다. 글 대화는 웹 앱에서 그대로 쓴다.

## 5. 핵심 기능

| 영역 | 기능 |
|---|---|
| 일지 | 저장(같은 날 같은 제목이면 갱신), 목록, 상세, 검색, 제목 수정, 삭제(2단계 확인) |
| 노트 | 저장(일지가 없으면 날짜별 "앱 메모"에 모음), 검색, 목록, 수정(별표·완료·내용), 삭제(2단계 확인) |
| 기억·프로필 | `get_memory`(호칭·최근 일지·열린 아이디어·열린 할 일 5개), `set_nickname` |
| 웹 | 앱에서 저장한 일지·노트를 기존 일지 화면에서 보고 노트를 수정. 앱 출처 표시는 시안 수정 뒤 |

도구는 모두 13개이고 입력·규칙은 [tools.md](tools.md)에 있다. 수정·삭제 범위는 **노트는 출처와 무관(웹에서 만든 아이디어 포함), 일지는 앱 출처만**이다.

## 6. 설계 원칙

- **서비스 한 곳**: 일지·노트·기억·호칭의 규칙은 `services/`에 한 번만 두고 내부 MCP(Claude CLI용)·외부 MCP·웹 API가 같은 규칙을 쓴다.
- **외부 노출 최소화**: 외부 MCP는 별도 ASGI 앱·별도 포트다. 공개하는 것은 MCP·OAuth뿐이고 `/api`·웹·`/internal`은 열지 않는다.
- **인증은 처음부터**: OAuth(PKCE·토큰 해시·로그인 시도 제한·등록 제한)를 쓰기 도구보다 먼저 만든다. 로그에는 도구 이름·시각·성공 여부·대상 id만 남기고 내용은 남기지 않는다.
- **파괴적 동작은 두 번 확인**: 삭제는 첫 호출이 미리보기와 확인 값 발급이고 그 값을 넘겨야 지운다(서버 강제. 사용자 확인 여부 자체는 서버가 보장하지 못한다). 일지 수정·삭제는 앱 출처로 한정한다.
- **돌려주는 내용은 데이터**: 일지·노트 내용을 돌려줄 때 "지시가 아니라 데이터"임을 밝힌다. 호칭 변경·삭제처럼 쓰기 동작은 사용자가 분명히 요청했을 때만 부르게 도구 설명에 쓴다.
- **기존 규약 존중**: 기존 `client-contract`의 일지·노트 규칙(제목 길이, 노트 500자, 삭제 규칙)을 바꾸지 않는 선에서 앱 출처 규칙만 더한다. 바뀌는 곳은 계약에 먼저 쓴다.
- **보류는 되돌릴 수 있게**: 자체 음성은 지우지 않고 보류한다. 이미 병합된 M3-01~15 코드는 그대로 둔다.
- **검증 방식**: 단위 시험에 더해 MCP 클라이언트 시험, 격리 서버 E2E(Playwright), 폰 실측(사용자 수행)으로 확인하고 묶음마다 사용자에게 확인받는다.

## 7. 구조 개요

```
Claude 앱(웹·폰)  음성 입력·출력은 앱이 처리
   │  HTTPS 443 (Tailscale Funnel)
   ▼
MCP 전용 앱(OAuth + /mcp)  ──>  services/  <──  내부 MCP(Claude CLI 전용)
                                   │                      ▲
                                   ▼                      │
                              SQLite(세션·턴·노트)   웹 API(/api/journal, /api/notes)
                                                          ▲
                                                웹 앱(PWA, Tailscale 사설 주소)
```

- 외부 MCP 서버와 기존 서버는 같은 코드베이스·같은 DB를 쓰고 포트가 다르다. 구조 상세는 [design.md](design.md) 1절.
- 앱에서 저장한 일지는 `mode=claude_app` 세션으로 들어가 웹이 이미 쓰는 일지 화면에 나온다.

## 8. 성공 기준

| ID | 기준 |
|---|---|
| MS-01 | 폰 Claude 앱 음성으로 "오늘은 여기까지"라고 하면 일지가 저장되고 웹 일지 화면에 보인다 |
| MS-02 | "저장된 아이디어를 목록으로 보여 줘"에 아이디어 목록을 말로 알려 준다(웹에서 만든 아이디어 포함) |
| MS-03 | 앱 음성으로 노트 별표·완료·내용 수정·삭제와 호칭 변경이 되고, 삭제는 확인 값 없이 한 번의 호출로 지워지지 않는다 |
| MS-04 | 외부 포트에서 `/api`·웹·`/internal`에 접근할 수 없고 인증 없는 `/mcp` 호출은 거부된다 |
| MS-05 | 웹에서 고친 노트가 앱의 `get_journal`·`list_notes`에 반영되고, 앱에서 지운 노트가 웹에서 사라진다 |
| MS-06 | 기존 웹 API·내부 MCP·웹 E2E 시험이 서비스 추출 뒤에도 그대로 통과한다 |

앱 음성 쪽 동작(도구 호출 안정성, 첫 호출 지연 로딩)은 앱의 영역이라 MS-01~03은 구현 뒤 폰 실측으로만 확인할 수 있다. 목표 수치(지연 등)는 정하지 않는다.

## 9. 하지 않는 것과 보류

- 자체 음성 처리(STT/TTS, 끼어들기, 오프라인 큐, 병합, 맞장구, 쉬기)는 **보류**다. 앱 경로를 폰에서 써 본 뒤 사용자가 재개 여부를 정한다.
- `trailTalk-MCP`의 `spike.db`에 쌓인 일지는 v2로 옮기지 않는다.
- 화면 시안은 수정하지 않는다. 앱 일지 출처 표시와 "이어서 하기" 숨김 화면은 시안 수정 뒤에 구현한다.
- 앱 쪽 계정 지침(말투·페르소나)과 커넥터 설정은 서버가 통제하지 않는다.
- Claude 앱 음성 모드의 도구 호출 방식·지연은 바꿀 수 없다.

## 10. 알려진 한계와 미결 사항

| 항목 | 내용 |
|---|---|
| Funnel·Serve 포트 | 현재 계약은 Serve가 443으로 사설 PWA를 연다. Funnel(443)을 MCP 전용으로 쓰려면 Serve의 포트를 옮겨야 할 수 있다. 실제 가능 여부는 구현 첫 작업에서 확인한다(MA-03) |
| 두 프로세스의 SQLite | 외부 앱과 기존 서버가 같은 파일을 쓴다. WAL·경합 시험으로 확인하고, 문제면 같은 프로세스의 별도 포트 리스너로 바꾼다 |
| 첫 도구 호출 실패 | 원형 기록에 앱의 도구 지연 로딩으로 첫 호출이 실패하고 재시도하면 성공하는 현상이 있다. 서버가 막을 수 없다. 폰 효과는 미검증이다 |
| 호칭 변경 반영 | 다음 대화부터 반영한다고 문서화했다. 진행 중 글 대화 프롬프트에 즉시 반영되는지는 확인 필요(MA-09) |
| 웹 노트 삭제 | 웹에는 노트 삭제 API가 없어 앱 음성만의 새 기능이다. 열린 대화의 Claude 맥락에는 남을 수 있다 |

## 11. 운영상 주의

- 검증용 서버(포트 8100 등)는 기존 규칙대로 DB·첨부·오디오·CLI 작업 폴더를 모두 임시 경로로 바꿔 띄운다. 사용자의 실제 서버(8000)와 DB는 건드리지 않는다.
- OAuth 소유자 비밀번호(16자 이상)와 공개 주소는 환경변수로만 받고 저장소·로그·문서에 값을 쓰지 않는다. `.env.example`에는 키 이름만 둔다.
- 실제 Claude 앱·Tailscale·폰을 쓰는 확인(MA-03, MA-12)은 실행 직전에 사용자에게 알린다.
- `trailTalk-MCP` 저장소는 참고용이며 수정하지 않는다. 코드를 가져올 때는 v2 규약에 맞춰 복사해 쓴다.

# 설계: Claude 앱 MCP 연계

결정 사항과 범위는 [README.md](README.md), 도구별 명세는 [tools.md](tools.md)에 있다. 이 문서의 이름(파일·함수·열)은 제안이며 구현 때 코드 규약에 맞춰 정한다.

## 1. 구조

```
Claude 앱(웹·폰, 음성 입력·출력은 앱이 처리)
   │  HTTPS 443 (Tailscale Funnel)
   ▼
MCP 전용 서버  ── OAuth(/.well-known/*, /authorize, /token, /register, 로그인 페이지)
   │            └ MCP(Streamable HTTP, /mcp)
   ▼
services/ (일지·노트·기억)  ◄── 내부 MCP(/internal/mcp, Claude CLI 전용)와 공유
   ▼
DB(기존 conversation_session · turn · note + OAuth 테이블)
   ▲
웹 PWA ── 기존 /api/journal, /api/notes (Tailscale 사설 주소, 인증 없음 그대로)
```

### 1.1 외부 MCP는 별도 ASGI 앱·별도 포트로 둔다 (결정됨, 2026-10-30)

Tailscale Funnel은 포트로 노출하므로 기존 서버(8000)를 그대로 Funnel에 열면 인증이 없는 `/api/*`와 웹 화면이 인터넷에 공개된다. 이는 현재 규칙(Spec 9 "공개 Funnel은 쓰지 않는다", 계약 1.2)과도 어긋난다. 그래서 같은 코드베이스에서 **MCP·OAuth 경로만 가진 두 번째 ASGI 앱**을 다른 포트(예: 8400)로 띄우고 Funnel은 그 포트만 가리키게 한다. DB와 `services/`는 두 앱이 같은 파일·같은 코드를 쓴다.

- 대안: 한 앱에 `/mcp`를 붙이고 리버스 프록시가 `/mcp`·OAuth 경로만 통과시킨다. 프록시 설정 실수가 곧 노출 사고라서 권장하지 않는다.
- **포트 충돌(확인 필요).** 현재 계약 1.2는 Tailscale Serve가 443으로 tailnet에만 HTTPS를 연다고 쓴다. Tailscale에서 Serve와 Funnel은 외부 포트(443·8443·10000)를 공유하고, 원형 기록은 "Claude 서버는 443만 접속하고 8443은 거절한다"이다. 따라서 **Funnel(443)은 MCP 전용 포트만 가리키고, 사설 PWA용 Serve는 다른 포트(예: 8443)로 옮기거나 Serve 443을 쓰지 않아야** 한다. 한 포트에 두 용도를 겹치지 않는 것이 이 설계의 전제이며, 실제 가능 여부는 구현 첫 작업에서 `tailscale serve/funnel status`로 확인한다. PWA 주소가 바뀌면 `ALLOWED_ORIGINS`·폰 설정·README가 함께 바뀐다.
- **MA-03 확인 결과(2026-10-30, 읽기 전용 `tailscale serve status`·`funnel status`)**: 이 Mac의 Funnel 443은 `/`를 `127.0.0.1:8400`(원형 `trailTalk-MCP`가 쓰는 MCP 포트) 하나만 가리키고, 8000(API)·5173(웹)은 Funnel에 없다. 곧 MCP 포트만 공개되는 배치가 이미 성립해 있다. 이 구성은 사용자 설정이므로 바꾸지 않았다. 아직 확인하지 못한 것: PWA를 tailnet 전용으로 다른 외부 포트(예: 8443)의 Serve로 여는 구성(`tailscale serve --bg --https=8443 http://127.0.0.1:8000`)이 Funnel 443과 공존하는지는 설정을 바꿔야 해서 MA-12(폰 실측) 전에 사용자 승인 아래 확인한다. 그 전까지 PWA는 `http://127.0.0.1:5173` 또는 Mac의 다른 접속 방법을 쓴다. 원형 서버를 끄고 v2 외부 서버(`./run.sh --mcp`)를 같은 8400에 띄우면 Funnel을 다시 설정하지 않아도 된다.
- SQLite를 두 프로세스가 쓰므로 연결마다 `journal_mode=WAL`과 `busy_timeout=5000`을 걸었고(`app/db/session.py`), 두 프로세스가 같은 파일에 동시에 쓰는 시험이 있다(`tests/test_mcp_external_guard.py`).
- `run.sh`에 MCP 서버 실행·종료를 더한다(`--mcp` 같은 옵션, 구현 때 정함).

## 2. 인증

`trailTalk-MCP`의 `app/oauth.py`·`app/login.py`·`app/config.py`를 이식한다(원본은 수정하지 않고 복사해 v2 규약에 맞춘다).

| 항목 | 내용 |
|---|---|
| 방식 | OAuth 2.1 인가 코드 + PKCE, 동적 클라이언트 등록(DCR). Claude 앱이 처음 연결할 때 자동으로 거친다 |
| 소유자 확인 | 인가 화면에서 소유자 비밀번호로 로그인(16자 이상, 환경변수, 저장소에 두지 않음) |
| 리다이렉트 허용 | 기본 `https://claude.ai/api/mcp/auth_callback`만. 목록은 설정으로만 바꾼다 |
| 공개 주소 | `https`만(로컬 시험은 `localhost`만 http 허용). 끝 슬래시·경로 금지. MCP 주소는 공개 주소 + `/mcp` |
| 토큰 | 접근·갱신 토큰은 해시로만 저장한다. 폐기·만료·갱신을 지원한다 |
| 저장 | 새 테이블(클라이언트·인가 코드·토큰). Alembic 리비전이 필요하다 |
| 로그 | 도구 호출은 이름·시각·성공 여부·대상 id(8자)만 남기고 인자·결과 내용은 남기지 않는다(`trailTalk-MCP`의 `calls.jsonl` 방식에 id를 더해 사고 추적을 가능하게 한다) |
| 등록(DCR) 제한 | 클라이언트 등록 수 상한과 오래된 미사용 등록 정리(원형 `_prune_clients`). 리다이렉트는 허용 목록 하나만 |
| 로그인 방어 | 비밀번호 시도 횟수 제한·지연·잠금, 비교는 상수 시간. 구현: 실패마다 1초 지연, 10분 안 5회 실패하면 10분 잠금. **한계**: 잠금은 전역이라 외부인이 로그인 요청 ID를 만들어 실패를 반복하면 소유자도 잠시 잠긴다(가용성 저하, 비밀번호 추측은 늘지 않는다). 대기 중인 로그인 요청은 100개로 제한한다(가득 차면 소유자도 최대 10분 새 로그인을 시작하지 못하는 같은 종류의 한계) |
| 프로토콜 검증 | `state` 확인, PKCE `S256`만 허용, 토큰 수명 값 명시(구현 때 정함), 토큰의 대상(`resource`) 검증, 공개 주소 외 `Host` 헤더 거부(MCP SDK의 TransportSecuritySettings) |
| 분실 대응 | 소유자 비밀번호 교체 절차와 발급 토큰 전체 폐기 명령을 `run.sh`와 같은 곳에 둔다 |

### 2.1 기존 보안 규칙과의 관계

- client-contract 1.5의 변경성 요청 CSRF 규칙은 `/api/*`용이다. 면제는 `/internal/*`뿐이므로, 외부 MCP 앱은 **자기 경로에 한해 별도 규칙**으로 정한다. 쿠키가 아니라 `Authorization: Bearer` 토큰으로만 인증하고, 로그인 페이지 폼에는 자체 CSRF 방어(상태 토큰)를 둔다. 이 서술을 계약 1.5와 Spec 보안 절에 더해야 한다([doc-changes.md](doc-changes.md)).
- `/internal/mcp`는 그대로 루프백 전용·프록시 경유 거부를 유지한다. 외부 앱은 이 경로를 노출하지 않는다.

## 3. 데이터 매핑

`trailTalk-MCP`의 `Journal` 한 장을 v2의 세션·노트로 나눠 담는다.

| 앱 도구 인자 | v2 저장 위치 | 비고 |
|---|---|---|
| `title` | `ConversationSession.title` | 같은 날 같은 제목이면 갱신(3.2). 앱에서 `rename_journal`로 고치면 `title_edited=true` |
| `summary` | `ConversationSession.summary` | 길이 1,000자 이하. v2 열은 문자열(Text)이고 계약 3.1의 `summary`는 줄 목록이므로, 서버가 줄바꿈으로 나눠 보여 주는 기존 변환을 그대로 쓴다. 웹 규약은 첫 줄이 결론이라 첫 줄을 결론으로 쓰도록 도구 설명에 안내한다 |
| `ideas`·`todos`·`memos` | `Note`(`kind`=idea/todo/memo) | 갱신 때 기존 노트를 유지하고 없는 내용만 더한다(3.3) |
| `tags` | `ConversationSession.tags` | 최대 10개, 각 30자 이하 |
| `transcript` | `Turn` 행 | 3.4 |
| (자동) | `mode`=새 값 `claude_app`, `status=ended`, `started_at`=저장 시각, `ended_at`=같은 값, `extract_status=done`, `persona_id`·`system_prompt`·`cli_session_id`=null | `SessionMode` 확장은 Alembic 필요(열이 비네이티브 enum + 검사 제약) |

### 3.1 새로 필요한 스키마

- `SessionMode`에 `claude_app` 추가(문자열 16자 이내라 열 길이는 충분).
- "앱 메모" 세션을 일반 앱 일지와 구분하는 방법(**결정됨, 2026-10-30**): **전용 열**(`app_kind`: null | `journal` | `memo`)로 구분한다. 제목 규칙은 쓰지 않는다. 사용자가 일지를 같은 제목으로 만들거나 고쳐도 섞이지 않는다.
- OAuth 테이블 3종(2절).

### 3.2 같은 날 같은 제목 = 갱신

`trailTalk-MCP`의 규칙을 이어받는다. 기준 날짜는 서버 시간대(`Asia/Seoul`)의 현지 날짜다. 새 일지는 `summary`가 필요하고, 갱신은 `summary`·`tags`·`transcript`에서 넘긴 항목만 바꾸고 생략한 항목은 그대로 둔다(`tags=[]`은 비움). 노트(`ideas`·`todos`·`memos`)는 갱신해도 지우지 않는다(3.3). 앱 출처 판정(웹 API의 출처 필드 `source: "app"`, 일지 수정·삭제 허용 판정)은 `mode=claude_app`으로 하고, `app_kind`는 그 안에서 일지(`journal`)와 앱 메모(`memo`)를 가른다. 갱신 대상 조회 조건은 `mode=claude_app`·`app_kind=journal`·현지 날짜·제목이다. 웹에서 앱 일지 제목을 같은 날 같은 제목으로 고치면 갱신 대상이 두 건이 되므로, **웹 `PATCH`의 제목 수정도 앱 세션이면 같은 날 중복을 거부**하고(제목 길이는 웹 1~200자, 앱 도구 1~100자로 다르지만 이 규칙을 계약 3.2에 쓴다. 갱신은 **조회 후 갱신**이고 `app_day` 유니크 인덱스가 최후의 방어선이다. 동시 호출로 인덱스 충돌(IntegrityError)이 나면 다시 조회해 갱신하는 재시도를 한 번 하고, 제목 수정(`rename_journal`·웹 PATCH)의 충돌은 409로 돌려준다. 웹 PATCH로 앱 메모 세션의 제목을 바꾸는 것도 거부한다(앱 메모 제목은 서버가 정한다, 409).

### 3.3 노트

- 일지에 속한 노트: `save_journal`이 만든다. **갱신 때 기존 노트를 유지한다**: 같은 일지의 노트 안에서 같은 종류이고 내용이 같은(공백을 하나로 줄이고 대소문자를 무시) 노트는 그대로 두어 id·별표·완료·웹 수정 내용을 보존하고, 없는 내용만 새 노트로 더한다. 넘긴 목록에 없는 기존 노트도, `[]`을 넘겨도 지우지 않는다. 삭제는 `delete_note`뿐이다. 원형 `sync_journal_notes`는 종류만으로 전체 노트에서 공백 정규화 비교를 하지만, v2는 **이 일지의 노트로 범위를 한정**하고 대소문자도 무시한다(v2 신규 규칙). 같은 날(서울 기준) 앱 메모 세션에 같은 종류·같은 내용의 노트가 있으면 새로 만들지 않고 **그 노트를 이 일지로 옮긴다**(id·별표·완료 보존). 다른 날 앱 메모와 웹 노트는 옮기지 않는다. 노트가 모두 옮겨져 비게 된 앱 메모 세션은 지운다(목록에 '노트 0개' 앱 메모가 남지 않게). 이후 `update_note`·`delete_note`로 개별 수정·삭제한다. 앱 메모 세션의 마지막 노트를 지우면 빈 앱 메모 세션도 함께 지운다.
- 일지 없이 저장하는 노트(`save_note`): **호출 시각의 현지 날짜**(자정을 넘기면 새 날짜) `app_kind=memo` 세션이 없으면 만들고 거기에 붙인다. 날짜 키 열 `app_day`(현지 날짜)에 부분 유니크 인덱스(`app_kind='memo'`일 때 `app_day`)를 두어 병렬 호출이 같은 날 세션을 둘 만들지 못하게 한다(SQLite 부분 인덱스 지원은 구현 때 확인). 앱 일지 쪽도 `app_kind='journal'`일 때 (`app_day`, 제목) 유일 인덱스를 둔다. 앱 메모 세션은 `extract_status=done`·`checks=[]`·`summary`는 비어 있다. `rename_journal`은 앱 메모에 쓸 수 없다(제목은 서버가 정함). 웹 목록에는 요약 줄 없이 제목과 노트 개수로 보인다. `save_journal`의 갱신 조회는 `app_kind=journal`만 대상으로 하고 앱 메모는 제외한다. 이 세션은 일지 목록에 "그날의 앱 메모" 하나로 보인다. 제목은 서버가 정한다(예: "앱 메모 · 10월 30일").
- `Note.content`는 1~500자(`NOTE_MAX_CHARS`). 앱에서 이보다 긴 항목을 넘기면 도구가 오류로 거절한다.
- 웹에서 고친 노트와 앱의 `update_note`는 같은 `Note`를 바꾸며 **마지막 쓴 것이 남는다**(낙관적 잠금 없음). 앱은 웹에서 만든 노트도 고칠 수 있다(8절 범위).

### 3.4 `transcript`

앱이 넘기는 대화 전문은 자유 텍스트(최대 20,000자)다. 선택지는 둘이다.

1. **(결정됨, 2026-10-30)** 줄 앞 머리표("나:"·"Claude:" 등)가 있으면 `Turn`(role user/assistant)으로 풀고, 없으면 사용자 한 턴으로 둔다. 웹 일지 전문 탭과 `search_conversations`가 그대로 동작한다.
2. (채택하지 않음) 별도 텍스트 열에 두고 검색만 한다. 전문 탭이 비어 보인다.

`Turn`으로 풀 때 화자 이름은 `persona_name`이 아니라 도구 인자(또는 "Claude")를 쓴다(NFR-08: 캐릭터 이름을 코드에 두지 않음).

## 4. `get_memory`와 `set_nickname`

돌려주는 내용(텍스트): 지금 시각(서울 기준), 호칭, 최근 일지(제목·요약), 아직 닫지 않은(`done=false`) 아이디어, 아직 닫지 않은 할 일(**생성 시각 최신순으로 5개까지, 결정됨**). 서버가 글 대화 프롬프트에 넣는 `load_memory`(`server/app/persona/memory.py`: 최근 요약·열린 아이디어·열린 할 일, 예산 `fit_to_budget`)를 **같은 함수로 재사용**해 앱과 글 대화가 같은 기억을 보게 한다. 앱용으로 문자열 서식만 다르게 만든다. 호칭은 `UserProfile`에서 읽는다. `load_memory`는 열린 할 일과 관심사도 담는다. 앱용 서식 단계에서 **열린 할 일은 포함하되 최근 5개로 제한**하고(걷는 중 음성으로 듣기에 길어지지 않게), **관심사는 뺀다**. 5개 상한은 `load_memory`의 기존 `MAX_TODOS`와 같은 값이다(별도 설정 없음, 시험으로 고정). 호칭이 없으면 "호칭: 아직 정하지 않음" 한 줄을 넣는다. 더 보려면 `list_notes(kind=todo)`를 쓴다. 앱 메모 세션은 요약이 없으므로(`summary` null) 최근 일지에서는 빠지고 노트만 열린 아이디어로 잡힌다. 이 동작을 시험으로 고정한다.

`set_nickname`은 내부 MCP의 같은 이름 도구(`server/app/mcp/server.py`)의 규칙을 서비스로 옮겨 재사용한다: `Nickname` 검증(1~20자 한 줄), "님·씨"를 뺀 부분 2글자 이상. 내부 도구는 "이번 사용자 발화에 나온 호칭만" 받지만 외부 앱에서는 서버가 발화를 알 수 없어 이 검사를 뺀다. 호칭은 프로필 하나라 웹 글 대화와 공유된다.

## 5. 코드 배치 (제안)

- `server/app/services/`에 일지·노트·기억 서비스를 둔다(저장·조회·검색·수정·삭제 규칙). 기존 `server/app/mcp/server.py`의 `save_note`·`search_notes`·`search_conversations` 로직과 `server/app/api/journal.py`의 삭제·제목 수정·노트 수정(PATCH) 규칙을 여기로 옮겨 **세 곳(내부 MCP, 외부 MCP, 웹 API)이 같은 규칙을 쓰게** 한다. 이 리팩터링은 기존 시험이 그대로 통과해야 한다.
- `server/app/mcp_external/`(가칭)에 외부 앱, OAuth, 도구 등록을 둔다.
- 내부 MCP의 `save_note`는 `X-TrailTalk-Session`으로 정해진 런타임 세션에 묶여 있다. 서비스로 옮길 때 "세션을 인자로 받는" 시그니처로 바꾸고, 내부 MCP는 자기 세션을, 외부 MCP는 앱 메모 세션을 넘긴다.
- 도구 표기: 읽기 전용은 `read_only_hint`, 삭제는 `destructive_hint`를 단다(`trailTalk-MCP`와 같음).

## 6. 웹에 미치는 영향 (시안은 수정하지 않는다)

앱에서 저장한 일지를 웹이 보여 주려면 기존 동작 몇 가지를 손봐야 한다. 이 항목들은 **계약(`client-contract.md` 3절)과 서버 동작 변경**이라서 구현 전에 문서에 먼저 반영한다.

| 기존 동작 | 문제 | 필요한 변경 |
|---|---|---|
| 일지 목록은 사용자가 한마디도 안 한 대화를 뺀다(3.1) | 앱 일지는 `Turn`이 없을 수 있어 목록에서 사라진다 | `claude_app` 세션은 턴 수와 무관하게 목록에 포함 |
| 항목에 출처 정보가 없다 | 웹이 앱 일지를 알아볼 수 없다 | 목록·상세 항목에 출처 필드(예: `source: "app" \| "web"`) 추가, `npm run gen:api`로 타입 갱신 |
| 끝난 대화 다시 열기·"이어서 하기"·"음성으로 이어서"(2.11) | 앱 세션에는 페르소나·CLI 세션이 없어 이어갈 수 없다 | `claude_app` 세션은 다시 열기를 409로 거절하고, 웹은 출처가 앱이면 버튼을 숨긴다 |
| 일지 다시 정리(`POST /api/journal/{id}/retry`) | 앱 일지는 정리가 필요 없다 | `claude_app`은 `journal_status`를 `done`으로 두고 retry는 아무것도 하지 않는다 |
| 진행 중(`active`)·쉬는 중(`paused`) 삭제 규칙 | 앱 세션은 항상 `ended` | 영향 없음 |

화면 쪽은 위 "버튼 숨김"과 출처 표시가 필요하다. 출처 표시(알약 등)는 시안이 없으므로 **시안을 수정한 뒤에 구현한다(결정, 2026-10-30)**. 시안 수정은 사용자의 별도 지시가 있을 때 하며, 그때까지 이 문서는 시안을 고치지 않는다. 서버 쪽 변경(목록 노출 규칙, 출처 필드, 다시 열기 거절)은 시안과 무관하게 먼저 구현한다.

## 7. 검증 계획

| 층 | 내용 |
|---|---|
| 서비스 단위 시험 | 저장·갱신(같은 날 같은 제목)·부분 갱신·삭제·제목 수정·노트 수정·검색·기억. 기존 시험은 그대로 통과 |
| MCP 시험 | `mcp` 클라이언트로 도구 13개 호출, 인자 검증 오류, 인증 없는 요청 거부, 만료·폐기 토큰 거부. `delete_journal`·`delete_note`는 확인 값 없이는 지우지 않는지, 맞는 확인 값으로 지우는지, 틀린·만료·다른 대상의 확인 값은 거절하는지, `update_note`·`delete_note`가 웹 노트에도 동작하고 `rename_journal`·`delete_journal`이 웹 일지를 거절하는지, `set_nickname`의 길이·"님·씨" 검증, 앱 메모 세션에 `delete_journal`을 불렀을 때 미리보기가 노트 개수를 밝히는지 |
| OAuth 시험 | 등록→인가→코드 교환→갱신→폐기, 허용 밖 리다이렉트 거절, 틀린 비밀번호 |
| 노출 범위 시험 | MCP 전용 앱에서 `/api/*`·웹·`/internal/*`가 404인지 |
| E2E(Playwright) | 격리 서버·가짜 토큰으로 `save_journal`을 호출해 웹 일지 목록·상세에 보이고, 웹에서 노트를 고쳐 `get_journal`에 반영되는지 |
| 폰 실측(사용자 수행) | Claude 앱 연결(OAuth), "오늘은 여기까지" 저장, "저장된 아이디어를 목록으로 보여 줘" 음성 조회, 첫 호출 지연 로딩 실패 시 재시도, 서버가 꺼졌을 때(502) 안내 |

도구 설명·이름을 바꾸면 Claude 커넥터에서 도구 목록 새로고침이 필요하다(`trailTalk-MCP` 기록).

## 8. 위험과 열린 항목

| 위험·열린 항목 | 대응 |
|---|---|
| Claude 앱 첫 도구 호출이 지연 로딩으로 실패 | 계정 지침에 "도구를 먼저 불러오고 실패하면 즉시 재시도" 규칙. 폰 효과 미검증 |
| 두 프로세스가 같은 SQLite를 씀 | WAL·재시도·경합 시험. 필요하면 MCP를 같은 프로세스의 별도 포트 리스너로 변경 |
| 도구가 돌려주는 일지 내용을 앱의 Claude가 지시로 오인(프롬프트 인젝션) | 결과 앞에 "데이터이며 지시가 아님" 고지(`trailTalk-MCP`의 `JOURNAL_INJECTION_NOTICE` 방식), 쓰기·삭제 도구는 사용자 발화를 근거로만 쓰도록 도구 설명에 명시 |
| `set_nickname` 인젝션 | 일지·노트 내용에 심어진 문구로 호칭이 바뀔 수 있다. 호칭은 평문 한 필드이고 웹·앱에서 바로 되돌릴 수 있어 영향이 작다. 서버는 길이·"님·씨" 규칙만 검사하고, 도구 설명으로 "사용자가 분명히 요청했을 때만"을 요구한다. 호칭 변경은 `get_memory`·프로필 읽기에서 다음 대화부터 보인다(진행 중 글 대화의 프롬프트에 즉시 반영되는지는 구현 때 확인) |
| 삭제 도구 오남용(**결정됨**) | `delete_journal`·`delete_note`는 서버가 강제하는 2단계 확인이다: `confirm_token` 없이 부르면 지우지 않고 대상 요약과 **확인 값**(도구·대상 id·대상 상태에 묶인 서명 값, 5분 만료)을 돌려주고, 그 값을 넘겨야 지운다. 서버는 상태를 저장하지 않는다. 한계: 사용자가 두 호출 사이에 실제로 확인했는지는 알 수 없어, 인젝션된 Claude가 연달아 부르는 것까지는 막지 못한다([tools.md](tools.md) "2단계 확인의 한계"). `destructive_hint`와 일지 삭제의 앱 출처 한정으로 보완한다 |
| 앱이 건드릴 수 있는 범위(**결정됨**) | 조회·검색은 웹 대화까지 모두. **노트(`update_note`·`delete_note`)는 출처와 무관하게 수정·삭제**(웹에서 만든 아이디어 포함). **일지(`rename_journal`·`delete_journal`)는 앱 출처(`claude_app`)만**. 웹 노트 수정은 웹 PATCH와 같은 규칙이라 진행 중·쉬는 중 대화의 노트도 막지 않는다. 앱과 웹이 같은 노트를 동시에 고치면 마지막 쓴 것이 남는다. 노트 삭제는 웹에 API가 없는 새 기능이라 삭제된 노트가 열려 있는 대화의 CLI 맥락에 남아 있을 수 있다(다음 턴 기억부터 빠진다) |
| 앱 세션이 고아·정리 작업의 대상으로 오인 | `purge_orphans`(첨부)·추출 작업이 `claude_app` 세션을 건드리지 않는지 구현 때 확인하고 시험으로 고정 |
| 쓰기 폭주 | 도구 호출은 전역(단일 사용자)으로 슬라이딩 60초당 60회, 쓰기(저장·수정·삭제)는 현지 날짜(`Asia/Seoul`) 기준 하루 200건이 초기값이다(설정으로 변경). 글자 수 상한은 항목 길이 한도가 대신한다. 구현은 MA-06, 시험은 MA-07·08 |
| 웹 노트 삭제의 비대칭 | 웹에는 노트 삭제 UI·API가 없어, 웹에서 본 노트가 앱 음성 한 번(확인 값 두 호출)으로 사라지는 경로가 새로 생긴다. 2단계 확인과 `destructive_hint`로 보완하고, 웹에 삭제 버튼을 더할지는 별개 결정이다 |
| 계정 지침(제니 말투 등)은 서버가 통제하지 못함 | 지침 원본을 문서로 두고 입력란과 일치시킨다(`trailTalk-MCP/docs/jenny-account-instructions.md` 방식) |
| 앱 일지의 출처 표시 UI(**결정됨**) | 시안 수정 뒤에 구현한다. 시안 수정은 별도 지시를 기다린다. 서버 쪽은 먼저 구현 가능 |
| `transcript` 처리 | **결정됨**: `Turn`으로 풀기(3.4). 머리표 해석 규칙은 구현 때 시험으로 고정 |

# TrailTalk × Claude 앱 MCP 연계 Spec

작성일: 2026-10-30. 상태: **제안(미구현)**. 이 문서는 [Intent.md](Intent.md)의 의도를 구현 가능한 명세로 풀어 쓴다. 구조·데이터 매핑은 [design.md](design.md), 도구별 입력·규칙은 [tools.md](tools.md), 작업·진행은 [implementation-plan.md](implementation-plan.md), 결정은 [README.md](README.md)가 근거다. 기존 [docs/Spec.md](../Spec.md)(이하 "기존 Spec")와 [client-contract.md](../client-contract.md)(이하 "계약")를 고치지 않고 덧붙이며, 승인 뒤 반영할 곳은 [doc-changes.md](doc-changes.md)에 있다.

- **기존 규칙 계승**: 일지·노트 규칙(제목 길이, 노트 1~500자, 삭제 규칙, 시간대)은 기존 Spec·계약을 그대로 따른다. 이 문서가 바꾸는 곳은 앱 출처 규칙뿐이며 그때는 `[MCP]`로 표시한다.
- **ID**: 요구사항은 `MFR-xx`(기능)·`MNFR-xx`(비기능), 결정은 `MD-xx`로 매겨 기존 ID와 겹치지 않게 한다. 기존 FR-19(일지 조회 MCP, P2)는 이 연계로 확장되어 P1로 올린다([doc-changes.md](doc-changes.md) 2절).
- **사실과 추정**: 앱 쪽 동작(도구 호출 안정성, 첫 호출 지연 로딩, 커넥터 접속 조건)은 `trailTalk-MCP` 기록과 일반적인 MCP 동작에 근거하며 v2에서 실측하지 않았다. 구현 뒤 폰에서 확인한다(11절).

## 1. 범위

| 구분 | 포함 | 제외 |
|---|---|---|
| 플랫폼 | 기존 FastAPI 서버·웹 PWA에 **외부 MCP 서버**를 더한다. 서버는 본인 Mac, 웹은 Tailscale 사설 주소, MCP만 Funnel(HTTPS 443)로 공개 | 서버 API·웹 화면의 인터넷 공개, 다중 사용자 |
| 음성 | 음성 입력·출력은 **Claude 앱**이 처리한다 | 자체 STT/TTS·VAD·끼어들기·오프라인 큐·병합·맞장구·쉬기(**보류**) |
| 기록 | 앱에서 저장한 일지·노트를 웹이 보여 주고 노트를 수정한다 | `trailTalk-MCP`의 `spike.db` 이관 |
| 도구 | 일지 6·노트 5·기억/프로필 2, 모두 13개 | 검색(웹)·이메일·첨부 등 기존 대화용 도구의 외부 노출 |
| 화면 | 기존 일지 화면에 앱 일지가 보인다 | 앱 출처 표시·"이어서 하기" 숨김 UI는 시안 수정 뒤(MA-13), 화면 시안 수정 |

앱 쪽 계정 지침(말투·페르소나)과 커넥터 설정은 서버가 통제하지 않는다.

## 2. 용어

- **앱 일지**: Claude 앱이 `save_journal`로 저장한 일지. `mode=claude_app`·`app_kind=journal` 세션 하나다. 상태는 항상 `ended`이다.
- **앱 메모**: 일지 없이 `save_note`로 저장한 노트를 날짜별로 모으는 세션(`mode=claude_app`·`app_kind=memo`). 목록에는 "그날의 앱 메모" 하나로 보인다.
- **앱 출처**: `mode=claude_app`인 세션(앱 일지와 앱 메모). 웹 API의 `source: "app"`이다.
- **웹 출처**: `mode`가 `text`·`voice`인 세션. `source: "web"`이다.
- **외부 MCP**: Claude 앱이 접속하는 `/mcp` 서버(OAuth 보호). **내부 MCP**(`/internal/mcp`)는 Claude CLI 전용으로 기존 그대로이며 이 연계의 범위가 아니다.
- **2단계 확인**: 삭제 도구를 `confirm_token` 없이 부르면 지우지 않고 대상 요약과 **확인 값**(도구·대상 id·대상 상태에 묶이고 5분 뒤 만료되는 서명 값)을 돌려주며, 그 값을 넘겨 다시 불러야 지운다. 서버는 상태를 저장하지 않는다. 사용자가 두 호출 사이에 확인했는지는 서버가 알 수 없다(9절).
- **용어 주의**: 기존 Spec의 "외부 MCP"(FR-25·D8·5.6)는 v2가 **호출하는** 바깥 서버이고, 이 문서의 "외부 MCP"는 Claude 앱이 **호출하는** v2의 서버다. 기존 문서에 반영할 때는 후자를 "앱 연결 MCP"로 부르는 것을 권장한다.

| ID | 항목 | 기준 |

## 4. 아키텍처

```
Claude 앱 ──HTTPS 443(Funnel)──> MCP 전용 ASGI 앱 ──> services/ <── 내부 MCP(CLI)
                                   (/mcp, OAuth)          │              ▲
                                                          ▼              │
                                                    SQLite  <── 웹 API(/api/*) <── 웹 PWA(사설 주소)
```

- **분리**: 외부 MCP는 같은 코드베이스의 **별도 ASGI 앱·별도 포트**(예: 8400)다. 기존 서버(8000)를 Funnel에 열지 않는다. 대안(프록시 허용 목록)은 설정 실수가 곧 노출 사고라서 채택하지 않는다(MD-01).
- **공유 서비스**: `server/app/services/`에 일지·노트·기억·호칭 규칙을 한 번만 두고 내부 MCP·외부 MCP·웹 API가 호출한다. 노트 저장은 세션을 인자로 받는다(내부는 런타임 세션, 외부는 앱 메모 세션).
- **코드 배치(제안)**: 외부 앱·OAuth·도구 등록은 `server/app/mcp_external/`(가칭). 구현 때 코드 규약에 맞춰 이름을 정한다.
- **포트 배치(확인 필요)**: 기존 계약은 Serve가 443으로 tailnet에 PWA를 연다. Serve와 Funnel은 외부 포트를 공유하므로 Funnel(443)은 MCP 전용 포트만, 사설 PWA는 다른 포트로 두는 배치가 전제다. 가능 여부는 MA-03에서 확인한다.
- **DB**: 두 프로세스가 같은 SQLite를 쓴다. WAL·재시도·경합 시험으로 확인하고, 문제면 같은 프로세스의 별도 포트 리스너로 바꾼다.

## 5. 핵심 동작 명세

공통: 삭제 확인 값의 규격(서명 키·만료·묶는 값)은 [tools.md](tools.md) "확인 값 규격"을 따른다.

### 5.1 OAuth

원형 `trailTalk-MCP`(`app/oauth.py`·`login.py`·`config.py`)를 v2 규약으로 옮긴다(원본 수정 금지).

| 항목 | 규칙 |
|---|---|
| 흐름 | 동적 클라이언트 등록(DCR) → 인가(소유자 비밀번호 로그인) → 코드 교환 → 접근 토큰, 갱신, 폐기 |
| 경로 | 원형을 따른다: `/.well-known/*`, `/authorize`, `/token`, `/register`, 로그인 페이지, MCP는 `/mcp`. 정확한 경로·메타데이터는 구현 때 확정 |
| 리다이렉트 | 기본 `https://claude.ai/api/mcp/auth_callback`만 허용. 목록은 설정으로만 바꾼다 |
| 공개 주소 | `https`만(로컬 시험은 `localhost`만 http). 끝 슬래시·경로 금지. 소유자 비밀번호는 16자 이상, 환경변수로만 받는다. 공개 주소·비밀번호가 없으면 서버를 띄우지 않는다 |
| 보강 | 로그인 시도 제한·지연·잠금(상수 시간 비교), 클라이언트 등록 수 상한과 미사용 등록 정리, `state` 확인, PKCE `S256`만, `resource`(대상) 검증, 공개 주소 외 `Host` 거부, 토큰 수명 명시(값은 구현 때) |
| 저장 | 클라이언트·인가 코드·토큰 테이블 3종. 접근·갱신 토큰은 해시로만 저장한다 |
| 분실 대응 | 소유자 비밀번호 교체와 발급 토큰 전체 폐기 명령을 제공한다 |

### 5.2 일지 저장 (`save_journal`)

| 항목 | 규칙 |
|---|---|
| 입력 | `title`(1~100자), `summary`(≤1,000자), `ideas`·`todos`·`memos`(문자열 목록, 항목 ≤500자), `tags`(≤10개, 항목 ≤30자), `transcript`(≤20,000자). 시그니처 상세는 [tools.md](tools.md) |
| 신규·갱신 | 서버 시간대(`Asia/Seoul`)의 현지 날짜 + `mode=claude_app`·`app_kind=journal` + 제목으로 조회한다. 없으면 새로 만들고(이때 `summary` 필요), 있으면 `summary`·`tags`·`transcript`는 넘긴 것만 바꾼다(생략=그대로, `tags=[]`=비움). 조회는 `app_kind=journal`만 대상으로 하고 `app_day`·제목 유일 인덱스가 중복을 막는다 |
| 세션 값 | `mode=claude_app`, `status=ended`, `started_at=ended_at=저장 시각`, `extract_status=done`, `checks=[]`(null이 아니어야 웹이 새 형식으로 그리고 "다시 정리" 대상이 되지 않는다), `app_kind=journal`, `app_day`=저장 시각의 현지 날짜, `persona_id`·`system_prompt`·`cli_session_id`=null, `title_edited=false` |
| 요약 | 문자열(Text)로 저장한다. 웹 규약은 첫 줄이 결론이라 도구 설명이 첫 줄을 결론으로 쓰게 안내한다. 줄 목록 변환은 기존 규칙 |
| 노트 | `ideas`·`todos`·`memos`를 `Note`(kind 해당 값)로 저장한다. **갱신 때 기존 노트를 유지**한다: 같은 일지의 노트 안에서 같은 종류이고 내용이 같은(공백을 하나로 줄이고 대소문자를 무시) 노트는 그대로 두어 id·별표·완료·웹 수정 내용을 보존하고 없는 내용만 더한다. 넘긴 목록에 없는 기존 노트나 `[]`로는 지우지 않는다(삭제는 `delete_note`). 원형 `sync_journal_notes`는 종류만으로 전체 노트에서 공백 정규화 비교를 하지만, v2는 이 일지의 노트로 범위를 한정하고 대소문자도 무시한다(v2 신규 규칙). 같은 날 앱 메모에 같은 종류·같은 내용의 노트가 있으면 새로 만들지 않고 그 노트를 일지로 옮긴다(id·별표·완료 보존, 노트가 모두 옮겨져 빈 앱 메모 세션은 지운다). 동시 저장으로 `app_day` 인덱스 충돌이 나면 다시 조회해 갱신하는 재시도를 한 번 한다 |
| 전문 | 갱신 때 앱 일지의 `Turn`을 새로 만든다. `transcript`의 줄 머리표("나:"·"Claude:" 등)가 있으면 `Turn`(role user/assistant)으로 풀고, 없으면 사용자 한 턴이다. 화자 이름은 코드에 두지 않는다(NFR-08). 머리표 해석 규칙은 구현 때 시험으로 고정 |
| 결과 | id(8자), 바뀐 항목, 현재 아이디어·할 일·메모 개수를 알려 준다 |

### 5.3 일지 조회·수정·삭제

| 도구 | 규칙 |
|---|---|
| `list_journals` | 최신순. `keyword`는 제목·요약·태그·노트·대화 전문에서 낱말(최대 3개)이 모두 든 것. `from_date`·`to_date`, `limit` 1~30(기본 10). 웹·앱 출처 모두 |
| `get_journal` | 요약, 노트(★별표·✓완료), 태그. `format`(text/markdown), `include_transcript`(기본 false) |
| `search_conversations` | 저장된 전문(`Turn`)에서 낱말(최대 3개) 모두 든 말을 최신순 최대 8건, 앞뒤 말과 함께 |
| `rename_journal` | **앱 출처의 일지만**(앱 메모는 제목을 서버가 정하므로 거절). 1~100자, 같은 날 같은 제목의 앱 일지가 있으면 거부, 성공하면 `title_edited=true` |
| `delete_journal` | **앱 출처만**. 2단계 확인(확인 값). 미리보기에 제목·날짜·노트 개수를 밝힌다. 앱 메모 세션도 앱 출처라 지울 수 있으며 그날 앱 메모 노트가 모두 사라진다. 지우면 그 일지의 노트·전문도 함께 지워진다(웹 `DELETE`와 같음). 웹 일지 id는 거절 |

id는 목록·검색 결과에 앞 8자를 보여 주고 다른 도구는 4~36자 접두사를 받는다. 여러 건이 일치하면 오류로 더 긴 id를 요청한다.

### 5.4 노트

| 도구 | 규칙 |
|---|---|
| `save_note` | `kind`(idea/todo/memo), `content`(1~500자). 일지가 없으면 그날(현지 날짜) 앱 메모 세션에 붙이고, 없으면 만든다. 앱 메모 제목은 서버가 정한다(예: "앱 메모 · 10월 30일") |
| `search_notes` | `keyword`, `days`(1~365, 기본 30). 최대 10건, 날짜·종류·내용·id |
| `list_notes` | `kind?`, `status`(open/done/all, 기본 open), `starred?`, `limit`(1~50, 기본 20). 별표 먼저, 그다음 최신순. 각 줄에 **출처(앱/웹)** 를 밝힌다 |
| `update_note` | `content?`(1~500자), `starred?`, `done?`. 넘긴 항목만 바꾼다. **웹에서 만든 노트도 고칠 수 있다.** 웹 `PATCH /api/notes/{id}`와 같은 검증이며 세션 상태 제한이 없다. 아이디어를 `done`으로 닫으면 다음 대화의 기억에서 빠진다 |
| `delete_note` | 2단계 확인(확인 값). **웹에서 만든 노트도 지울 수 있다.** 웹에는 노트 삭제 API가 없으므로 서비스 계층의 새 기능이다. 메모 노트를 지우면 그 일지의 인용 번호가 다시 매겨질 수 있다. 열린 웹 대화의 CLI 맥락에는 남을 수 있고 다음 턴 기억부터 빠진다 |

### 5.5 기억과 호칭

| 도구 | 규칙 |
|---|---|
| `get_memory` | 대화 시작 때 부른다. 지금 시각(서울 기준, 아침·저녁을 추측하지 않음), 호칭, 최근 일지(제목·요약), 열린 아이디어(`done=false`), 열린 할 일(생성 시각 최신순 5개). 관심사는 넣지 않는다. 글 대화의 `load_memory`(최근 요약·열린 아이디어·열린 할 일, 글자 예산 `fit_to_budget`)를 **같은 함수로 재사용**하고 앱용 서식만 다르다. 앱 메모 세션은 요약이 없어 최근 일지에서 빠지고 그 노트만 열린 아이디어·할 일로 잡힌다. 5개 상한은 `load_memory`의 기존 `MAX_TODOS`와 같은 값이다(별도 설정 없음). 호칭이 없으면 "호칭: 아직 정하지 않음" 한 줄을 넣는다 |
| `set_nickname` | `nickname` 1~20자 한 줄, "님·씨"를 뺀 부분이 두 글자 이상. 프로필(`UserProfile.nickname`) 하나를 웹 글 대화와 공유한다. 내부 도구와 달리 "이번 사용자 발화에 나온 호칭" 대조는 서버가 발화를 알 수 없어 할 수 없고, 도구 설명이 방어선이다. 다음 대화부터 반영한다(진행 중 글 대화 프롬프트에 즉시 반영되는지는 구현 때 확인) |

### 5.6 공통 도구 규칙

- 읽기 전용 도구는 `read_only_hint`, 삭제 도구는 `destructive_hint`를 단다.
- 결과 오류는 한국어 한 문장이다. 내부 예외·경로·SQL은 내보내지 않는다. 웹 일지에 대한 수정·삭제 거절, 앱 메모 제목 수정 거절, id 모호·없음, 확인 값 오류, 속도·저장량 초과의 문구와 구분은 [tools.md](tools.md) "오류 응답"을 따른다.
- 쓰기·삭제·호칭 변경은 사용자가 분명히 요청했을 때만 부르도록 도구 설명에 쓴다.
- 도구 이름·설명을 바꾸면 Claude 커넥터에서 도구 목록을 새로고침해야 반영된다.

## 6. 데이터 모델 변경

기존 Spec 6절 모델에 다음을 더한다. 스키마 변경은 Alembic(모델을 바꾸는 커밋에 리비전 포함). 열거 CHECK 변경은 batch로 교체한다.

| 대상 | 변경 |
|---|---|
| `conversation_session.mode` | 값 `claude_app` 추가(문자열 16자 이내, 비네이티브 enum+CHECK 교체) |
| `conversation_session.app_kind` | 새 열, 문자열 nullable: `journal` \| `memo`(웹 세션은 null). 앱 메모와 앱 일지를 구분하며 제목 규칙을 쓰지 않는다 |
| `conversation_session.app_day` | 새 열, 날짜 nullable(앱 세션만). 앱 일지·앱 메모의 현지 날짜 키. 부분 유니크 인덱스: `app_kind='memo'`이면 `app_day`, `app_kind='journal'`이면 (`app_day`, `title`). 병렬 `save_note`·`save_journal`의 중복 생성을 막는다(SQLite 부분 인덱스 지원은 구현 때 확인). 앱 메모 세션은 `extract_status=done`·`checks=[]`이고 요약은 비어 있다 |
| OAuth 테이블 3종 | 클라이언트(등록 정보 JSON), 인가 코드, 토큰(접근·갱신 모두 해시). 정확한 열은 원형을 따라 구현 때 정한다 |
| 변경 없음 | `turn`, `note`, `user_profile` 구조는 그대로. 앱 일지의 `transcript`는 `turn`, 항목은 `note`로 들어간다 |

앱 세션은 `persona`·CLI 관련 열이 비어 있다. `purge_orphans`·추출 작업이 `claude_app` 세션을 고아·정리 대상으로 오인하지 않는지 시험으로 고정한다.

## 7. 서버 API 변경 (웹)

외부 MCP 자체는 REST가 아니라 MCP 프로토콜이다. 아래는 앱 일지를 웹이 다루게 하려고 기존 API에 더하는 변경이다. 서버 API를 바꾸면 `npm run gen:api`로 `schema.d.ts`를 다시 만들어 함께 커밋한다.

| 대상 | 변경 |
|---|---|
| `GET /api/journal` 목록 | "사용자가 한마디도 하지 않은 대화는 빠진다" 규칙에 예외: `claude_app` 세션은 턴 수와 무관하게 나온다. 항목에 `source: "app" \| "web"` 추가 |
| `GET /api/journal/{id}` 상세 | 항목에 `source` 추가. 앱 세션의 전문 화자 이름(`persona_name`)은 기본 페르소나가 아니라 "Claude"를 내려준다(앱 대화 상대의 표시 이름이며 캐릭터 이름이 아니다. 값은 코드에 박지 않고 설정(예: `APP_SPEAKER_NAME`, 기본 "Claude")에 둔다. NFR-08과 충돌하지 않는다) |
| `POST /api/journal/{id}/retry` | 앱 세션이면 아무것도 하지 않는다(`journal_status`는 `done`이고 `checks`는 `[]`이라 "다시 정리" 대상이 아니다). 웹이 이 버튼을 숨기는 UI는 MA-13 |
| 다시 열기(계약 2.11) | 앱 세션은 409로 거절(코드는 구현 때 정해 계약 9절 오류 응답 표에 추가) |
| `PATCH /api/journal/{id}` | 앱 일지는 같은 날 같은 제목을 거부하고(409, 코드는 구현 때), 앱 메모 세션의 제목은 바꿀 수 없다(409) |
| `PATCH /api/notes/{id}` | 변경 없음. 앱 노트·웹 노트 모두 같은 규칙 |
| `DELETE /api/journal/{id}` | 변경 없음 |

노트 삭제 API는 웹에 없다. 웹에 삭제 버튼을 더할지는 별개 결정이다(이 연계의 범위 밖).

## 8. 화면

- 기존 일지 목록·상세가 앱 일지를 그대로 보여 주고 노트를 수정한다. 데이터 형식이 같아 추가 개발이 거의 없다.
- 앱 일지 출처 표시(알약 등)와 앱 세션의 "이어서 하기"·"음성으로 이어서" 숨김은 시안이 없다. **시안을 수정한 뒤에 구현한다**(MA-13, 사용자 별도 지시 대기). 그 전에는 서버 변경(7절)만 하고 화면은 그대로다.
- 화면 시안은 이번 범위에서 수정하지 않는다.

## 9. 보안과 개인정보

- **공개 범위**: Funnel은 MCP·OAuth 포트에만 쓴다. `/api`·웹·`/internal`은 공개하지 않는다. 기존 Spec 9절의 "공개 Funnel은 쓰지 않는다"와 계약 1.2는 이 예외를 반영해 고친다([doc-changes.md](doc-changes.md)).
- **CSRF**: 계약 1.5의 규칙은 `/api/*`용이며 면제는 `/internal/*`뿐이다. 외부 MCP 앱은 쿠키가 아니라 `Authorization: Bearer`로만 인증하므로 이 규칙의 대상이 아니고, 로그인 폼은 자체 CSRF 방어(상태 토큰)를 둔다.
- **내부 MCP**: `/internal/mcp`는 루프백 전용·프록시 경유 거부를 그대로 유지한다. 외부 앱은 이 경로를 노출하지 않는다.
- **인젝션**: 일지·노트·전문은 사용자 대화나 외부 검색 내용이 섞일 수 있어 앱의 Claude가 쓰기·삭제를 지시받을 수 있다. 방어: 결과에 데이터 고지, 서버가 강제하는 삭제 2단계 확인(확인 값 없이는 한 호출로 지울 수 없음. 단 두 호출 사이에 사용자가 확인했는지는 서버가 알 수 없어 인젝션된 Claude의 연속 호출까지는 막지 못함), 일지 수정·삭제를 앱 출처로 한정, 쓰기 도구 설명에 사용자 요청 조건 명시. `set_nickname`은 평문 한 필드이고 바로 되돌릴 수 있어 영향이 작다.
- **로그**: 이름·시각·성공 여부·대상 id(8자)만 남긴다. 인자·결과 내용은 남기지 않는다.
- **비밀 값**: 소유자 비밀번호와 공개 주소는 환경변수로만 받는다. `.env.example`에는 키 이름만 둔다.
- **수정·삭제 범위 요약**: 앱 도구로 노트는 출처와 무관하게, 일지(제목 수정·삭제)는 앱 출처만 다룬다. 웹 대화(일지)의 삭제는 앱 도구로 할 수 없고 웹 API(`DELETE /api/journal/{id}`, 진행 중이면 409)로만 한다.

## 10. 규약 관리와 개발 규칙

- 서버 API·오류 코드·상태 규칙이 바뀌면 [계약](../client-contract.md)을 먼저 고친다(바꾸는 곳: 1.2, 1.5, 2.11, 3.1, 3.2, 3.3, 9. [doc-changes.md](doc-changes.md) 3절).
- 서비스 추출(MA-01·02)은 기존 시험이 그대로 통과해야 병합한다. 기존 시험을 삭제·skip·완화하려면 사용자 승인을 받는다.
- 모델을 바꾸면 Alembic 리비전, 서버 API를 바꾸면 `gen:api`를 같은 커밋에 넣는다.
- 브랜치·병합·리뷰는 CLAUDE.md를 따른다(묶음 하나당 브랜치 하나, 병합 승인 전 전체 검증·Playwright·서브에이전트 리뷰).
- `trailTalk-MCP`는 참고용이며 수정하지 않는다. 코드는 v2 규약에 맞춰 복사한다.

## 14. 성공 기준

| ID | 기준 |
|---|---|
| MS-01 | 폰 Claude 앱 음성으로 "오늘은 여기까지"라고 하면 일지가 저장되고 웹 일지 화면에 보인다 |
| MS-02 | "저장된 아이디어를 목록으로 보여 줘"에 아이디어 목록을 말로 알려 준다(웹에서 만든 아이디어 포함) |
| MS-03 | 앱 음성으로 노트 별표·완료·내용 수정·삭제와 호칭 변경이 되고, 삭제는 확인 값 없이 한 번의 호출로 지워지지 않는다 |
| MS-04 | 외부 포트에서 `/api`·웹·`/internal`에 접근할 수 없고 인증 없는 `/mcp` 호출은 거부된다 |
| MS-05 | 웹에서 고친 노트가 앱의 `get_journal`·`list_notes`에 반영되고, 앱에서 지운 노트가 웹에서 사라진다 |
| MS-06 | 기존 웹 API·내부 MCP·웹 E2E 시험이 서비스 추출 뒤에도 그대로 통과한다 |

MS-01~03은 앱 쪽 동작이라 폰 실측으로만 확인할 수 있다([Intent.md](Intent.md) 8절과 같은 기준).

# 구현 계획서: Claude 앱 MCP 연계 (가칭 마일스톤 MA)

작성일: 2026-10-30. 설계는 [design.md](design.md), 도구 명세는 [tools.md](tools.md), 결정은 [README.md](README.md), 기존 문서 반영안은 [doc-changes.md](doc-changes.md)에 있다. 이 문서는 **작업 ID·상태·완료 기준**의 정본이다. 기존 `docs/implementation-plan.md`(M0~M6)와 별개이며, 착수가 승인되면 그 문서의 대시보드·6절·7절에 한 줄 요약으로 연결한다([doc-changes.md](doc-changes.md) 4절).

## 1. 사용법과 갱신 규칙

- 상태: `대기` · `진행 중` · `완료` · `보류` · `막힘`. 작업을 시작·끝낼 때 이 문서의 상태를 갱신해 **같은 커밋**에 넣는다(CLAUDE.md).
- 브랜치와 병합은 CLAUDE.md 작업 규칙을 따른다: 묶음 하나당 브랜치 하나(`ma-a-services` 형식), 브랜치 안에서는 묻지 않고 커밋·푸시, `main` 병합은 사용자 승인 뒤. 승인 요청 전에 전체 검증, Playwright 실구동 검증, 독립 서브에이전트 diff 리뷰(지적 반영)를 통과시키고 결과를 보고한다.
- 문서만 바꾸는 변경(`docs/` 아래 전부)은 서브에이전트 diff 리뷰 뒤 `main`에 직접 커밋한다(CLAUDE.md 예외). 이 폴더 문서도 같다(2026-10-30 사용자 확인). 기존 문서 반영(MA-00b)은 2026-10-30 사용자 지시로 했다.
- 서버 API를 바꾸면 `cd web && npm run gen:api`로 `src/api/schema.d.ts`를 다시 만들어 함께 커밋한다. 모델을 바꾸면 Alembic 리비전을 같은 커밋에 넣는다.
- 기존 테스트를 삭제·skip하거나 기대값을 완화하려면 사용자 승인을 받는다. 서비스 계층 추출(MA-01·02)은 **기존 시험이 그대로 통과**하는 것이 기준이다.
- 화면 시안은 수정하지 않는다(사용자 지시). 시안이 필요한 작업(MA-13)은 시안 수정 지시를 기다린다.
- 실제 Claude 앱·Tailscale·폰이 필요한 작업(MA-03, MA-12)은 실행 직전에 사용자에게 알린다.

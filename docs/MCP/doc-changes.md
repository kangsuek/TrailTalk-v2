# 기존 문서 반영안

이 문서는 Intent·Spec·구현 계획서·클라이언트 계약에 옮길 변경 목록이다. 2026-10-30에 MA-00b로 옮겼다(남은 "구현 때" 항목은 각 문서에 "구현 때 정함"으로 표시). 화면 시안(`docs/design/`, 아티팩트)은 2026-10-30 사용자 지시로 이번 범위에서 제외한다.

반영 순서 제안: 계약·Spec을 먼저 고치고(코드 변경의 근거), 계획서는 마일스톤 착수 때 상세화한다. 문서만 바꾸는 변경이므로 CLAUDE.md 규칙대로 독립 서브에이전트 diff 리뷰 뒤 `main`에 직접 커밋한다.

## 1. Intent (`docs/Intent.md`)

25행의 "주 장면" 문장을 승인된 문구로 바꾼다.

> 주 장면은 걷는 중 이어폰으로 하는 음성 대화다. 음성 대화는 Claude 앱(MCP 연계)이 맡고, TrailTalk는 그 일지·노트를 저장하고 보여 준다. 자체 음성 처리(STT/TTS)는 보류한다. 글 대화는 그대로 유지한다.

25행의 바뀐 문구는 글 대화의 위상("음성이 어려울 때의 보조 수단")도 바꾼다. 음성 대화가 앱으로 옮겨 가므로 글 대화는 TrailTalk가 직접 하는 유일한 대화 수단이 된다. 이 변화를 Intent 본문(원칙·범위)에서 한 번 더 확인한다.

그 밖에 확인할 곳: 32행 기능 표의 "음성 대화(무음 1.8초 자동 전송, 끼어들기, 쉬기, 오프라인 보관 후 전송)"와 35행 설정 표의 보이스·말 속도·음성 원본 보관 — "보류" 표시를 단다. 76행 응답 지연 서술은 자체 음성 경로의 이력이라 그대로 두되 "보류 중" 각주를 단다.

## 3. 클라이언트 계약 (`docs/client-contract.md`)

변경 요약(0절)에 항목을 더하고, 아래 절을 고친다.

| 절 | 변경 |
|---|---|
| 1.2 폰 접속 | "서버 API에는 로그인이 없으므로 공개 주소(Funnel)로 열지 않는다"는 문장을 "MCP 전용 포트만 Funnel로 열고 서버 API는 열지 않는다"로 고친다. Serve(443)와 Funnel의 포트 배치(design.md 1.1)가 정해지면 폰 접속 주소·`ALLOWED_ORIGINS` 서술도 맞춘다 |
| 1.5 변경성 요청 보안 | 면제 서술에 "외부 MCP 앱은 `Authorization: Bearer`로만 인증하며 이 규칙의 대상이 아니다. 로그인 폼은 자체 CSRF 방어를 둔다"를 더한다 |
| 3.1 목록 | "사용자가 한마디도 하지 않은 대화는 빠진다"에 예외를 쓴다: 앱 일지·앱 메모 세션은 턴 수와 무관하게 나온다. 항목에 출처 필드(예: `source: "app" \| "web"`)를 더한다 |
| 3.2 상세와 정리 | 상세 항목에도 출처 필드. `POST /api/journal/{id}/retry`는 앱 세션이면 아무것도 하지 않는다. `PATCH /api/journal/{id}`는 앱 세션이면 같은 날 같은 제목을 거부한다(409, 코드는 구현 때 정함). 앱 세션의 `persona_name`은 설정값(기본 "Claude")을 내려주고(코드에 박지 않음) `checks=[]`로 새 형식을 쓴다. 앱이 메모 노트를 지우거나 노트를 고치면 `counts`와 메모 인용 번호(`cites`)가 달라질 수 있음을 적는다 |
| 3.3 노트 | 노트 삭제는 웹 API가 없고 앱 MCP만 제공한다는 점과, 앱이 웹 노트를 고칠 수 있다는 점(마지막 쓴 것이 남음)을 적는다. 웹에 노트 삭제 버튼·API를 더할지는 별개 결정 |
| 2.11 다시 열기 | 앱 세션은 409(코드는 구현 때 정해 9절 오류 응답 표에 추가)로 거절한다 |
| 오류 코드 표 | 새 코드가 필요하면 추가 |

서버 API가 바뀌므로 구현 때 `cd web && npm run gen:api`로 `src/api/schema.d.ts`를 다시 만들어 함께 커밋한다(CLAUDE.md).

## 4. 구현 계획서 (`docs/implementation-plan.md`)

- 2절 대시보드: "현재 작업/다음 작업"을 갱신한다. M3 묶음 D(`m3-d-verify`)는 보류로 표시하고 다음 작업은 새 마일스톤 착수 확인으로 쓴다.
- 6.1절 M3: 6.1.0 묶음별 진행 상태 표의 묶음 D 행에 "보류(2026-10-30 결정, 자체 음성 보류·Claude 앱 연계)". 6.1.1 표의 M3-16~19에 같은 표시와 보류 해제 조건. 완료한 M3-01~15는 그대로 둔다. 6.1.2 완료 기준·6.1.3 종료 체크리스트는 M3 "부분 종료(M3-01~15)"로 적고, 마일스톤 종료 확인은 보류 해제 시점으로 미룬다고 밝힌다.
- 6절 요약 표 M4: 음성 항목(끼어들기·오프라인 큐·병합·맞장구·쉬기·`prepare`)에 "보류" 표시. 시안 적용 이월분(대화 03·06·07)도 함께 보류.
- 새 절: 새 마일스톤(가칭 MA)을 4·5절 형식(작업 요약·완료 기준·종료 체크리스트)으로 상세화한다. 묶음 구성은 design.md 9절.
- 7절 요구사항 추적표: FR-19 행(우선순위·마일스톤) 갱신, 새 FR 추가.
- 8절 이월·결정: 이 결정과 근거(외부 노출은 MCP 전용 포트, `spike.db` 미이관, 시안 미수정)를 기록한다. 시안 관련 항목(기존 "시안 적용 이월" 기록)은 시안을 고치지 않았으므로 그대로 두고, **출처 표시 UI는 시안이 없다**는 점을 열린 항목으로 적는다.

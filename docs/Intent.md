# TrailTalk Intent

이 문서는 TrailTalk(v1)을 읽고 앱을 실제로 돌려 본 결과를 바탕으로, v2가 이어받아야 할 **의도(무엇을, 왜, 어떤 원칙으로)**를 정리한다. 구현 세부는 v1 저장소의 `docs/requirements-design.md`, `docs/client-contract.md`, `docs/handoff.md`가 기준이다.

## 1. 한 줄 정의

등산·산책 중 휴대폰을 꺼내지 않고 이어폰만으로 캐릭터 '제니'와 대화하며 아이디어를 넓히고, 그 대화를 자동으로 일지(요약·아이디어·할 일·메모)로 남기는 웹 앱(PWA)이다.

## 2. 왜 만드는가

- 매일 아침 등산하며 떠오르는 아이디어를 손으로 기록하기 어렵다.
- 혼자 걸을 때 생각을 받아 주고 넓혀 줄 대화 상대가 있으면 아이디어가 더 잘 나온다.
- 대화 상대가 적은 40~50대에게 친구 같은 말동무가 필요하다.

## 3. 목표

1. **핸즈프리**: 시작 버튼 한 번 뒤에는 화면 조작 없이 듣고, 말하고, 끝낸다.
2. **브레인스토밍**: 한 번에 질문 하나씩 던져 아이디어를 넓히고 구체화해 다음 행동까지 잇는다.
3. **자동 기록**: 대화 전문과 함께 아이디어·할 일·메모를 날짜별 일지로 남기고, 다음 대화에서 기억해 이어 간다.
4. **일관된 캐릭터**: 이름·성격·말투·보이스를 설정(페르소나 레이어)으로 입힌다. 모델의 고정 정체성이 아니다. 사용자 호칭은 세션 첫 인사에서만 쓰고 이후 답변에서는 붙이지 않는다.

## 4. 사용자와 사용 장면

- 사용자는 본인 한 명이다(단일 프로필, API에 로그인 없음). 서버는 본인 Mac에서 돌고, 폰은 Tailscale HTTPS로 접속한다.
- 주 장면은 걷는 중 이어폰으로 하는 음성 대화다. 글 대화는 음성이 어려울 때의 보조 수단이다.
- 대화가 끝나면 일지에서 정리 결과를 확인하고, 별표·완료로 아이디어를 관리한다.

## 5. 핵심 기능

| 영역 | 기능 |
|---|---|
| 대화 | 음성 대화(무음 1.8초 자동 전송, 끼어들기, 쉬기, 오프라인 보관 후 전송), 글 대화, 파일 첨부(이미지·텍스트·PDF) |
| 제니 도구 | 노트 저장, 지난 노트·대화 검색, 세션 요약, 쉬기·종료, 호칭·모델 변경, 이메일 발송, 웹 검색(국내 `search_naver`, 해외 `search_USA`, 폴백 `WebSearch`) |
| 일지 | 날짜별 목록, 제목 수정, 삭제(단건·선택), 상세(결론·알게 된 것·확인할 것·아이디어·할 일·메모·인용·전문), 같은 세션 이어서 하기, 다시 정리 |
| 설정 | 호칭, 이메일, 관심사, 보이스(미리 듣기), 말 속도, 대화 모델, 음성 원본 30일 보관 |
| 시작 화면 | 지난 아이디어 이어 가기 카드, 서버 연결 상태, Claude 남은 토큰 막대 |

화면은 하단 탭 세 개(대화·일지·설정)이며 일지 상세는 일지 탭 안의 화면이다.

## 6. 설계 원칙

- **클라이언트는 가볍게**: 클라이언트는 녹음·발화 감지(VAD)·재생만 맡는다. 문장 분할, 요약, 중복 제거처럼 서버가 할 수 있는 일은 서버에 둔다.
- **페르소나 분리**: 캐릭터 이름·성격·말투·보이스는 `personas/*.yaml`에만 두고 코드에 넣지 않는다. 시스템 프롬프트는 한 조립기에서만 만든다.
- **API 키 없는 Claude**: 서버에 로그인한 Claude CLI(`claude -p`)를 세션별 프로세스로 띄워 쓴다. CLI 실행 인자·환경은 한 곳에서만 정의한다.
- **즉시 기록**: 모든 턴은 오가는 즉시 DB에 쓴다. 끊겨도 그때까지는 남고, 오프라인 발화는 기기에 보관했다가 복구 후 전송한다(기록 유실 0).
- **규약 고정**: REST(`/api/*`), SSE 이벤트, 상태 머신, 클라이언트 설정값을 `client-contract`로 고정해 서버와 웹을 따로 고치고 테스트한다. OpenAPI에서 웹 타입을 생성한다.
- **순수 core**: 세션 상태 머신과 오프라인 큐는 UI·브라우저 API에 의존하지 않는 TypeScript로 두고, 마이크·재생·저장소는 인터페이스 뒤에 둔다.
- **개인정보**: 대화·음성·첨부는 본인 서버에만 저장하고 키·토큰은 서버에만 둔다. 예외는 사용자가 요청한 본인 이메일 발송뿐이다.
- **검증 방식**: 단위 테스트에 더해 Playwright로 실제 앱을 구동해 확인하고 마일스톤마다 사용자에게 확인받는다.

## 7. 구조 개요

```
웹 앱(PWA)  ──SSE/REST──>  FastAPI 서버  ──>  Claude CLI(세션별 프로세스) ──> Claude(구독)
 VAD·녹음·재생            페르소나 조립, STT/TTS,        │
 오프라인 큐              일지 추출, MCP 도구 서버       └─ MCP 도구(save_note, 검색 등)
                          SQLite(Alembic 마이그레이션)
외부: OpenAI STT/TTS, Tavily, 네이버 검색
```

- 서버: `app/api`(라우터), `app/services/conversation.py`(세션·턴 SSE), `app/llm`(CLI 관리), `app/mcp`(제니 도구), `app/persona`(프롬프트), `app/jobs`(세션 종료 추출·무발화 타임아웃·정리), `app/voice`(STT·TTS·문장 분할).
- 웹: `src/core`(상태 머신·큐), `src/platform`(브라우저 구현), `src/screens`(대화·일지·설정), `src/api`(클라이언트).

| NFR-07 | 제니 답변 샘플 20개 중 18개 이상이 톤 체크리스트 통과 |

## 9. v1의 알려진 한계와 미결 사항 (v2가 판단할 것)

- **응답 지연(v1 목표 3초 미달)**: v1 실사용 223턴(검색 제외)의 말 끝 → 첫 소리는 중앙값 7.45초, p90 10.62초였고 3초 이내는 0건(최소 4.67초)이다. 구간 중앙값은 무음 대기 1.85초, 음성 인식 0.88초, CLI 첫 글자 2.00초, 첫 문장 완성·합성 1.81초이며, 꼬리는 합성 지연(15초 걸린 턴 포함)과 Claude 첫 글자 편차에서 나온다. 무음 1.8초는 쪼개진 말을 막으려 유지하므로 목표를 위 NFR-01로 다시 정했다. 수단은 첫 문장을 짧게·일찍 끊어 합성, TTS 헤징·타임아웃, 맞장구 소리다.
- **쉬며 이어 말한 말이 쪼개져** 앞말에만 답하는 문제.
- **TTS 안정성**: 기본 모델 `gpt-4o-mini-tts`가 무작위로 멈춰 현재 `tts-1`(말투 지시 미적용)을 쓴다.
- **화면의 마크다운**: 답변 속 `**굵게**`·링크가 그대로 보인다(음성은 제거됨).
- **보안**: 인증 없는 `/api`가 tailnet에 열려 있어 CSRF 여지가 있다. Origin·Content-Type 검사를 검토해야 한다.
- 제니가 제안만 하고 사용자가 수락하지 않은 내용이 아이디어로 추출되는 경우, 호칭 변경 후 `--resume` 시 옛 호칭 잔존, iOS Safari 미확인.
- 남은 계획: 마크다운 내보내기(P2).

## 10. 운영상 주의

- 검증용 서버를 띄울 때는 DB뿐 아니라 **첨부·오디오·CLI 작업 폴더를 모두 임시 경로로** 바꾼다. 서버 시작 시 고아 첨부 정리(`purge_orphans`)가 DB에 없는 파일을 지우므로, 첨부 폴더(`ATTACHMENTS_DIR`)를 그대로 두면 실제 파일이 삭제된다. 이 때문에 v1 조사 중 실제 첨부 파일이 지워진 사고가 있었다.
- 사용자의 실제 서버(포트 8000)와 DB는 건드리지 않는다. 실제 Claude CLI와 OpenAI 호출은 사용량·과금이 있으므로 필요할 때만 쓴다.
